# 动态代理池接入设计（多厂商代理 API）

> 版本：v1（2026-09-16，待评审）
> 目标：为抓包链路增加「动态代理池」上游模式，首期接入 91HTTP（www.91http.com）开放 API，架构上预留多厂商扩展，设置中可下拉选择厂商。
> 归属：环境类全局配置（与监听地址/手动上游/ADB 同类，跨项目共享）。

---

## 一、背景与现状

PrismProxy 转发链路已有「上游代理」概念（`internal/proxy/server.go` + `tunnel.go`），设置位于「设置 → 网络 → 上游代理」，三种模式（`internal/settings/settings.go`）：

| 模式 | 值 | 行为 |
|---|---|---|
| 直连 | `direct` | 无上游（默认） |
| 手动代理 | `manual` | 单个静态 `host:port`，**无鉴权**，启动代理时固化到 `http.Transport.Proxy` |
| 跟随系统 | `system` | 读系统注册表 ProxyServer（跳过自身防环） |

现状限制：

1. 只能填一个静态代理地址，无法对接「API 提取、IP 有时效（分钟级）、自动轮换」的短效代理服务商。
2. 不支持代理鉴权（用户名/密码）：明文 HTTP 路径未注入 `Proxy-Authorization`，盲隧道 `dialViaUpstream` 的 CONNECT 请求也不带 `Proxy-Authorization`。
3. 上游地址在 `NewServerOpts` 时一次性固化，换 IP 必须重启代理（`SaveSettings` 对监听/上游变化走 needRestart）。

## 二、91HTTP API 梳理（首期厂商）

文档：`https://www.91http.com/api-docs/`，基址 `http://api.91http.com`（注意官方文档为 **http**，非 https）。

| 接口 | 方法/路径 | 关键参数 | 返回 |
|---|---|---|---|
| 提取 IP | GET `/v1/get-ip` | `trade_no`* `secret`* `num`* `format`*(text/json)；可选 `protocol`(1 http/2 socks)、`sep`(分隔符)、`time=1`(带过期时间)、`pw=1`(带鉴权账密)、`isp`、`province`、`city`、`filter=1`(过滤今日已提取) | text：每行 `ip:port`（带 time/pw 时为扩展行）；json：结构化列表 |
| 添加白名单 | GET `/v1/white-ip/add` | `trade_no` `secret` `add_ip` | json `{code,msg,...}` |
| 删除白名单 | GET `/v1/white-ip/del` | `trade_no` `secret` `del_ip` | json |
| 白名单列表 | GET `/v1/white-ip/get` | `trade_no` `secret` | `{code,msg,data:{max_white_ip,remain_white_ip,white_list:[...]}}` |
| 地区列表 | GET `/v1/tool/get-city-list` | `province?`（逗号分隔多省） | 省/市结构 |
| 业务详情 | GET `/v1/order/get-info` | `trade_no` `secret` | `{code,msg,data:{auth_username,auth_password,base_ip_quantity,surplus_ip_quantity,white_ip}}`（**仅按量套餐**） |

要点：

- 鉴权二选一：**终端 IP 白名单** 或 **用户名+密码**（账密来自业务详情 `auth_username/auth_password`；提示文案称「用户名为实例 id，密码为实例 id 后八位密码」）。
- IP 短效：提取结果可带「剩余可用秒数/过期时间」，到期需重新提取。
- 返回 `code` 成功值在不同接口示例里出现过 `0` 与 `200` 两种，**判定成功必须 `code==0||code==200`，不能只认一个**。
- 文档未给出 `/v1/get-ip?format=json` 与 `time=1&pw=1` 扩展行的确定字段样例（官方新版文档仅给 text 成功示例）。91http 另有一套老版接口（`pt/result_type/split`，返回 `data.proxy_list[]`，元素形如 `ip:port,地区,邮编,剩余秒数`），**与 v1 参数不通用**。
  - 实施策略：v1 优先请求 `format=json&time=1&pw=1`，按多种已知 JSON 形态做防御式解析（见 §5.4）；解析失败回退 `format=text` 按分隔符切行；真实字段以接入时真账号抓包为准（列为实施期验证项，先写解析单测夹具覆盖 text/json 两套样例）。
- 参考出站校验地址（官方文档示例）：`http://api.91http.com/v1/tool/get-my-ip`。

## 三、目标与非目标

### 目标
1. 新增上游模式 `pool`（动态代理池），抓包流量经厂商短效代理 IP 出站。
2. 多厂商账号配置：设置中**下拉选择厂商**（首期仅 91HTTP，架构可扩展），支持多套账号配置、命名、选择当前生效项。
3. IP 池自动提取、到期前自动续期、失败/耗尽自动补池；手动「立即提取 / 换一个 IP」。
4. 支持账密鉴权代理（HTTP 明文转发 + CONNECT 盲隧道两条路径都要补鉴权）。
5. 设置页展示池状态（当前出口 IP、剩余数、到期倒计时、套餐余量），提供「测试提取」与白名单辅助操作。
6. 复用现有保存/热应用框架；**切换池内 IP 不重启代理**（仅启用/停用池模式或改监听才走现有重启路径）。

### 非目标（首期不做）
- 不做按目标域名/规则分流到不同代理（全局单出口池；后续可在规则引擎维度扩展）。
- 不做 SOCKS 上游（91http `protocol=2` 预留字段，引擎本期仅 HTTP 代理；UI 首期锁定/隐藏 socks 选项）。
- 不做每请求自动轮换（抓包场景需要稳定出口便于 App 会话保持；仅提供「粘滞/手动换」+ 到期自动换，见 §6.3）。
- 不让 AI 分析 / Composer 旁路出站单独走池（v1 统一跟随现有上游解析；池模式下一并生效作为自然结果，不做独立开关）。
- 不内置任何具体业务方信息；厂商为通用代理服务商，属正常工具能力。

## 四、总体架构

```
设置 UI（NetworkTab 上游区 + 代理池子区）
        │ SaveSettings（环境类全局，沿用 SettingsView/白名单拷贝）
        ▼
settings.GlobalSettings.ProxyPool（配置）+ ProxyProviders[]（多账号）
        │
        ▼
internal/proxypool（新包）
  ├─ Provider 接口：Fetch/AccountInfo/Whitelist 能力
  ├─ provider_91http.go：91HTTP v1 适配器（防御式解析）
  ├─ registry.go：厂商注册表（id→构造器），首期注册 "91http"
  ├─ pool.go：Manager（提取/续期/轮换/状态/单飞/计数）
  └─ entry.go：ProxyEntry{Host,Port,Username,Password,ExpireAt,Meta}
        │ Resolver() func() (*UpstreamEndpoint, error) —— 线程安全、动态
        ▼
internal/proxy（改造）
  ├─ Options.UpstreamResolver（新增；优先于静态 UpstreamProxy）
  ├─ transport.Proxy 改为闭包：每次取当前 endpoint（含鉴权 URL）
  └─ tunnel.go：dialViaUpstream 接收 endpoint，CONNECT 带 Proxy-Authorization
        │
        ▼
App 装配（bindings_proxy.go startProxySnap）
  resolveUpstream(...) → pool 模式时返回 Manager.Resolver，Manager 生命周期挂 App
```

核心思路：把「启动时固化一个地址」改为「**每次建立上游连接时向 Resolver 取当前 endpoint**」。`http.Transport.Proxy` 本就是 `func(*http.Request) (*url.URL, error)`，天然支持动态返回；池内换 IP 只改 Manager 内部原子指针，传输层下一个连接即生效，无需重启。

## 五、配置与数据模型设计（settings 包）

### 5.1 上游模式常量
```go
const (
    UpstreamDirect = "direct"
    UpstreamManual = "manual"
    UpstreamSystem = "system"
    UpstreamPool   = "pool" // 新增：动态代理池
)
```

### 5.2 配置结构（环境类全局，落 config/settings.json）
```go
// GlobalSettings 新增
type GlobalSettings struct {
    // ...现有字段...
    ProxyPool ProxyPoolSettings `json:"proxyPool"`
}

// ProxyPoolSettings 动态代理池总配置（环境类、跨项目）
type ProxyPoolSettings struct {
    Enabled        bool                `json:"enabled"`        // 仅便于保存时判断；真正生效以 upstreamMode=="pool" 为准
    ActiveProvider string              `json:"activeProvider"` // 当前生效的账号配置 id（空=未选择）
    Providers      []ProxyProviderConf `json:"providers"`      // 多厂商/多账号配置清单
    Rotation       RotationConfig      `json:"rotation"`       // 轮换与续期策略
    OnEmpty        string              `json:"onEmpty"`        // 池耗尽/提取失败：direct 直连(默认) | error 拒绝
}

// ProxyProviderConf 一条厂商账号配置（厂商下拉选择；同厂商可多条=多账号）
type ProxyProviderConf struct {
    ID       string `json:"id"`                 // 本地生成唯一 id（与域名组 id 同规则 ^[a-z0-9][a-z0-9-]{0,63}$ 不够用，账号 id 允许更长随机串，单独定义）
    Name     string `json:"name"`               // 用户可读别名（必填，默认"厂商-尾号"）
    Vendor   string `json:"vendor"`             // 厂商 id：首期 "91http"；registry 校验存在性
    TradeNo  string `json:"tradeNo"`            // 91http 业务编号（通用字段名按厂商映射）
    Secret   string `json:"secret"`             // 91http 业务密钥（敏感，仅存本地 0600，不回显原值）
    Protocol string `json:"protocol,omitempty"` // "http"（首期仅 http；socks 预留不开放）
    // 提取参数
    FetchNum   int    `json:"fetchNum,omitempty"`   // 单次提取数量，默认 1（粘滞模式 1 即可）
    Province   string `json:"province,omitempty"`   // 省份筛选（可选）
    City       string `json:"city,omitempty"`       // 城市筛选（可选）
    ISP        string `json:"isp,omitempty"`        // 0 不筛选/1 电信/2 移动/3 联通（存字符串或 int，定义常量）
    FilterUsed bool   `json:"filterUsed,omitempty"` // filter=1 过滤今日已提取
    AuthMode   string `json:"authMode,omitempty"`   // "whitelist" | "userpass" | "auto"(默认 auto：优先账密，缺失则白名单)
    // 账密可选覆盖：一般由 order/get-info 自动获取；允许手填兜底（与 AI entries apiKey 同属敏感字段）
    Username string `json:"username,omitempty"`
    Password string `json:"password,omitempty"`
}

// RotationConfig 轮换/续期策略
type RotationConfig struct {
    Mode            string `json:"mode"`            // "sticky"（默认，到期才换/手动换）| "perRequest"（预留，首期 UI 不开放）
    RefreshAheadSec int    `json:"refreshAheadSec"` // 到期前多少秒提前续提，默认 30
    MinPoolSize     int    `json:"minPoolSize"`     // 池低于该数触发补池，默认 1
    MaxRetry        int    `json:"maxRetry"`        // 提取/建连失败重试次数，默认 2
}
```

说明：
- 字段命名按「通用代理池」语义，`TradeNo/Secret` 是 91http 特有凭据；新增厂商时优先复用通用键（如后续厂商用 `apiKey` 再在 conf 内增补可选字段 + 该厂商 adapter 自取），不为假想厂商提前抽象过度。
- `Secret/Password` 敏感：**不进 SettingsView 全量回传 DTO**（对齐 AI apiKey 红线），走独立掩码投影；本地 settings.json 权限 0600（现有文件权限策略），不写日志。
- 旧 settings.json 无 `proxyPool` 字段 → 零值反序列化，`UpstreamMode` 恒不为 `pool`，行为完全不变（兼容）。

### 5.3 厂商注册表（可扩展点）
```go
// internal/proxypool
type VendorID = string

const Vendor91HTTP VendorID = "91http"

// FetchResult 统一提取结果
type FetchResult struct {
    Entries      []ProxyEntry
    SurplusTotal int   // 套餐余量（厂商支持时）
    FetchedAt    time.Time
}

type ProxyEntry struct {
    Host      string    // 必填
    Port      int       // 必填
    Username  string    // 账密鉴权时
    Password  string
    ExpireAt  time.Time // 未知则零值（IsZero→不做到期续期，仅失败换）
    Region    string    // 归属地（展示用，可空）
    Source    VendorID
    Raw       string    // 原始行（排障，不进 UI 明文展示密钥）
}

// Provider 厂商能力接口
type Provider interface {
    Vendor() VendorID
    Fetch(ctx context.Context, conf ProxyProviderConf, n int) (*FetchResult, error)
    AccountInfo(ctx context.Context, conf ProxyProviderConf) (*AccountInfo, error) // 余量/账密/白名单 IP
    AddWhitelist(ctx context.Context, conf ProxyProviderConf, ip string) error
    DelWhitelist(ctx context.Context, conf ProxyProviderConf, ip string) error
    ListWhitelist(ctx context.Context, conf ProxyProviderConf) (*WhitelistInfo, error)
    // Cities 可选能力：地区列表（91http 有；用能力接口可选实现判断）
}
```
- `registry.go` 维护 `map[VendorID]func() Provider`；首期注册 `91http`。设置页厂商下拉由绑定方法 `ListProxyVendors() []VendorMeta` 提供（id/显示名/是否支持账密/是否支持白名单/是否支持地区），前端不硬编码厂商清单——**将来加厂商=新增一个 adapter + 注册一行，UI 自动出选项**。
- 厂商 HTTP 请求统一走独立 `http.Client`（短超时：连接 5s、整体 15s），**提取/管理请求直连，不经过 PrismProxy 自己**（防环：厂商 API 若经自身且自身上游是池→启动期死锁）。

### 5.4 91HTTP 适配器解析约定
- 请求固定带 `format=json&time=1&pw=1&num=n&protocol=1`，条件带 `isp/province/city/filter`。
- JSON 防御式解析（按真账号校准，先覆盖已知形态）：
  - 判成功：`code==0||code==200`。
  - 列表键候选：`data.list` / `data.proxy_list` / `data.ips` / 顶层 `data` 为数组；元素可能是对象（`ip/port`、`ip:port` 合一、`addr`、`expire_time/expire_time_str/ttl/remain`、`username/password`/`account/pwd`）或字符串扩展行。
  - text 回退：按 `sep`（默认 `\r\n`）切行，行内可能为 `ip:port` 或 `ip:port,expire,user,pwd` 等逗号段，按段数与位置保守解析，无法判定的段不臆造。
- 失败响应：`code` 非成功值或 HTTP 非 200，返回携带 `msg` 的错误（UI 直接展示，如「提取频繁/白名单未配置/余量不足」）。
- 账密：优先使用条目内 `user/pass`（pw=1 返回），其次 order/get-info 的 `auth_username/auth_password`，再其次配置手填；白名单模式则不发送账密。

### 5.5 校验（settings.ValidateEnv）
- `upstreamMode=="pool"` 时：`ActiveProvider` 必须在 Providers 中存在且 `Vendor` 已注册、`TradeNo/Secret` 非空（掩码保存场景要允许密钥空缺=保持原值，对齐 AI 保存语义）；校验失败拒绝保存并给中文错误。
- `FetchNum` 范围 1–100（超过厂商上限由厂商错误兜底）；`RefreshAheadSec` 0 时给默认 30；`OnEmpty` 枚举校验。
- 删除/停用当前 ActiveProvider：若代理正在跑，先停 Manager 并回退直连（对齐 ADB「取消 AutoSet 补一次清理」的收敛思路，避免池指向已删账号）。

## 六、代理池运行时（internal/proxypool/manager.go）

### 6.1 生命周期
- Manager 由 App 持有（与代理实例同生命周期范围），`startProxySnap` 解析到 pool 模式时 `EnsureManager(conf)`（配置变更则 rebuild），停止代理时 Manager 停止后台续期 goroutine（但可保留最近状态供 UI 查看；简化起见停代理即 Stop，重新启动重新提取）。
- 单飞：`singleflight` 或自建 `mu+inflight`，并发建连触发补池只发一次提取请求。
- Manager 持有「当前 endpoint」用 `atomic.Pointer[ProxyEntry]`（粘滞出口）+ 池切片（fetchNum>1 时）。

### 6.2 取当前上游（Resolver）
```go
// 返回当前应使用的上游；ok=false 且 err 非空时按 OnEmpty 决策
func (m *Manager) Resolver() func(ctx context.Context) (*Endpoint, error)
type Endpoint struct {
    Addr     string // host:port
    Username string
    Password string
}
```
- 池空：触发同步补池（带超时长尾：最多等 N 秒）；仍失败 → `OnEmpty=direct` 返回 `(nil,nil)`（引擎侧 nil=直连）并在状态中标红告警；`OnEmpty=error` 返回错误（HTTP 转发返回 502，CONNECT 回 502，**不静默用真实 IP 出站**）。

### 6.3 轮换与续期
- sticky（默认）：固定当前 entry；到期前 `RefreshAheadSec` 后台异步提新 IP，成功后原子切换（旧连接不断，新连接走新 IP）；切换时发状态事件刷新 UI 倒计时。
- 手动换 IP：绑定方法 `ProxyPoolRotate()` → 立即丢弃当前 entry 并补池。
- 建连失败计数：同一 entry 连续 Dial/上游 407/403/连接失败达到阈值（默认 2）→ 标记该 entry 坏，池内取下一个；池空则补池。**注意区分**：代理协议错误（407 鉴权、403 白名单）应直接给用户明确提示而不是无限重试。
- 厂商提取限流（91http 有最短提取间隔，错误 msg 通常提示）：补池失败按指数退避（如 2/5/10s，封顶 60s），不紧密轮询。

### 6.4 状态模型（供 UI / ctlapi）
```go
type PoolStatus struct {
    Running       bool      `json:"running"`
    Vendor        string    `json:"vendor"`
    ProviderName  string    `json:"providerName"`
    Current       *EndpointView `json:"current"` // host:port（含掩码，不含密码）、地区
    ExpireAt      int64     `json:"expireAt"` // unix 秒，0=未知
    RemainSec     int       `json:"remainSec"`
    PoolSize      int       `json:"poolSize"`
    SurplusTotal  int       `json:"surplusTotal"` // 套餐余量（-1=未知）
    LastFetchAt   int64     `json:"lastFetchAt"`
    LastError     string    `json:"lastError"`
    OnEmpty       string    `json:"onEmpty"`
    Fetching      bool      `json:"fetching"`
}
```
- 通过 Wails 事件 `proxypool:status` 节流推送（对齐现有 50ms 批量/状态事件习惯，到期倒计时 1s 刷新可由前端本地计时，后端只在状态变化时推）。

## 七、代理引擎改造（internal/proxy）

### 7.1 Options 增加动态解析
```go
type Options struct {
    UpstreamProxy    string                          // 保留：静态（manual/system 解析结果）
    UpstreamResolver func(ctx context.Context) (*UpstreamEndpoint, error) // 新增：pool 用，非 nil 时优先
    Engine           *rules.Holder
}
type UpstreamEndpoint struct {
    Addr, Username, Password string
}
```
- 装配优先级：resolver 非空（pool）→ 用 resolver；否则用静态 UpstreamProxy；都空=直连。
- 现有 `GuardUpstreamLoop` 保留并在 resolver 返回的 Addr 上同样做防环校验（池 IP 不会是本机，但防御保留）。

### 7.2 明文 HTTP / MITM 解密路径（http.Transport）
- 把 `s.transport.Proxy = http.ProxyURL(固定 URL)` 改为闭包：
```go
s.transport.Proxy = func(req *http.Request) (*url.URL, error) {
    ep, err := s.resolveUpstream(req.Context())
    if err !=nil { return nil, err }
    if ep == nil { return nil, nil } // 直连
    u := &url.URL{Scheme: "http", Host: ep.Addr}
    if ep.Username != "" { u.User = url.UserPassword(ep.Username, ep.Password) }
    return u, nil
}
```
Go Transport 会自动对上游代理的 401/407 用该 URL 的账密生成 `Proxy-Authorization: Basic`，并对 HTTPS 目标的 CONNECT 也自动带账密——**走 Transport 的路径无需手写鉴权头**（当前手动模式无账密所以没问题；池账密在 Transport 路径自动覆盖）。

### 7.3 盲隧道 CONNECT 路径（tunnel.go）
现状 `dialViaUpstream(proxyAddr,target,timeout)` 不带鉴权。改造：
- 签名增加 endpoint（或传 resolver）：`dialViaUpstream(ep *UpstreamEndpoint, target string, timeout time.Duration)`。
- CONNECT 请求在 `ep.Username!=""` 时加：
  `Proxy-Authorization: Basic base64(user:pass)`（用 `base64.StdEncoding`，与 net/http 口径一致）。
- 读响应区分 407：返回明确错误「上游代理要求鉴权/账密被拒」，触发 Manager 坏点处理与 UI 提示。
- 调用处（handleConnect 盲透传分支）先 `resolver(ctx)` 取 endpoint；nil 直连；err 且 OnEmpty=error 回 502。

### 7.4 抓包记录中的敏感信息
- 代理鉴权头由传输层/隧道层生成，**不写入 Flow 请求头记录**（Transport 层在代理连接上加的 Proxy-Authorization 不经过我们记录的请求头；手写 CONNECT 头也不入 Flow），密码不出现在抓包列表/详情/cURL 复制中（cURL 基于已记录头，天然不含）。
- MITM 解密目标站本身的 `Authorization` 记录规则不变。

## 八、App / 绑定 / ctlapi 设计

### 8.1 启动装配（bindings_proxy.go）
- `resolveUpstream` 扩展：`pool` 模式不再返回静态字符串，改为：
  - `EnsureProxyManager()`（读取 gcfg.ProxyPool + ActiveProvider 配置构造/重建 Manager，首跑同步提取一个 IP，失败按 OnEmpty）。
  - 给 `proxy.Options.UpstreamResolver` 赋 `manager.Resolver`；静态 `UpstreamProxy` 留空。
- `startProxySnap` 目前签名收 `(addr, upMode, upProxy)`；新增内部参数或改为收一个上游描述结构，避免再扩字符串参数（调用点：StartProxy、SaveSettings needRestart、startProxySnap；AI/Compose 不直接用池 resolver，保持现状）。
- 热应用语义（SaveSettings）：
  - `upstreamMode` 在 manual/system/direct 间切换、监听变化 → 现有 needRestart 重启代理。
  - direct/manual/system → pool、pool → 其他、或池账号关键凭据变化 → needRestart（Manager 需重建）。
  - **仅池内 IP 变化/手动换 IP/到期自动续期 → 不重启**（Manager 内部原子切换）。
  - 池非关键参数（如 Rotation、OnEmpty）变化 → 热更新 Manager 配置，尽量不重启。

### 8.2 新增 Wails 绑定（全部遵守 ≤2 返回值，末位 error；DTO 单结构）
| 绑定 | 作用 |
|---|---|
| `ListProxyVendors() ([]VendorMeta, error)` | 厂商下拉清单（registry 提供） |
| `ProxyPoolTestFetch(conf) (ProxyTestResult, error)` | 不保存配置，试提取：返回首个 `ip:port`、地区、到期、是否带账密、原始解析形态（供设置页「测试」） |
| `ProxyPoolStatus() (PoolStatus, error)` | 当前池状态 |
| `ProxyPoolRotate() (PoolStatus, error)` | 手动立即换 IP（仅 upstreamMode=pool 且代理运行中有效，否则错误提示） |
| `ProxyPoolAddWhitelist(ip?) (msg,error)` / `DelWhitelist(ip)` / `ListWhitelist()` | 白名单辅助；ip 空=自动查本机公网 IP（通过厂商 get-my-ip 或直连服务） |

- 敏感字段遵循掩码：SettingsView 不含 secret/password 原值；ProviderConf 出入设置表单时 secret 走「空=保持 / `__clear__`=清空」（复用 AI apiKey 成熟语义），或像 ADB 一样随表单往返——**本设计采用 AI 语义（更安全，密钥不入全量 DTO）**，ProviderConf 在 SettingsView 中以投影类型 `providerView{...hasSecret, secretMasked}` 呈现。
- wailsjs 三文件（App.d.ts/App.js/models.ts）+ mocks/app.ts 手动同步（铁律）。
- ctlapi：v1 至少提供只读 `cli proxy pool status` 与 `proxy pool rotate`（写操作经 ctl_bridge 适配）；厂商配置编辑仍走 GUI（避免 CLI 落 secret 的复杂度，列为非目标）。ctlService 接口加方法需同步 fakeService 编译断言。

### 9.1 上游代理区改造（NetworkTab.vue）

### 9.2 代理池子区（新组件 `pages/settings/ProxyPoolTab.vue` 或 NetworkTab 内联区块）
- **厂商**：n-select 下拉（选项来自 `ListProxyVendors`，首期=91HTTP）；下方「账号配置」n-select 选择已保存账号 + 「编辑/新增/删除」（多账号）。

- **白名单辅助**：展示当前白名单列表/配额（max/remain），`添加本机 IP 到白名单`（自动取公网 IP，二次确认）、单条删除。
- 空态：未选账号时给引导文案与 91http 后台链接（仅工具帮助，不含业务方信息）。
- 事件订阅 `proxypool:status`（在设置面板挂载时订阅，卸载移除；对齐现有事件生命周期管理）。

### 9.3 文案与风险
- pool 模式在状态栏/上游区明确标识「经代理池出站」，让用户知道当前出口非本机。
- OnEmpty=direct 时常驻浅色警示「代理失效将回退直连」；OnEmpty=error 时提示「代理失效时流量将被拒绝（更安全）」。

## 十、错误处理与可观测

| 场景 | 行为 |
|---|---|
| 厂商 API 不通/超时 | 补池退避重试；状态卡显示错误；已持有有效 IP 继续用旧 IP（不提前丢弃） |
| 提取返回 code 失败（限流/余量不足/白名单） | 展示厂商 msg；不更新当前出口；连续失败到 OnEmpty 策略 |
| 代理 407 鉴权失败 | 明确「账密错误或鉴权方式不匹配」；不无限重试；提示切换账密/白名单 |
| 代理 403/白名单拒绝 | 提示「终端公网 IP 未加白」，一键引导加白 |
| 池 IP 到期 | 提前 RefreshAhead 续提；续提失败到期后按 OnEmpty |
| 代理运行中删除当前账号 | SaveSettings 收敛：停 Manager，模式回退 direct 并提示 |
| 防环 | resolver 返回地址过 GuardUpstreamLoop；厂商 API 调用直连不经自身 |

- Manager 关键动作用现有 `log.Printf`（中文、与项目一致），**密钥/账密一律不打印**；可加 runtimeLog 状态行（对齐 ADB 日志习惯）。

## 十二、决策记录（2026-09-16 评审拍板）

1. **池耗尽策略（已拍板）**：在设置中提供用户可选项——「回退直连并警告」(direct) 或「断联拒绝出站」(error)，两种都保留，由用户自选；**默认 direct + UI 常驻警示**。

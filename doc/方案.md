# Prism / 棱镜 — 代理抓包工具技术方案

```
    ╱╲
   ╱  ╲     P R I S M
  ╱ ◇◇ ╲    棱镜 · 代理抓包工具
 ╱  ◇◇  ╲   "让加密流量，现出原形"
```

> **命名由来**：棱镜把混杂的白光分解为清晰可见的光谱 —— 正如本工具把加密混杂的网络流量解密为结构清晰、可读可查的请求列表。

| 定位 | 开源桌面级 HTTP(S) 调试代理，对标 Reqable |
| 技术栈 | Go（代理引擎）+ Wails v2 + Vue 3 / TypeScript |

---

## 一、项目定位与目标场景

不重复造轮子的边界：本工具聚焦「**抓包 + 看包**」，做到轻、快、稳，第一版不做改包/断点/弱网。

目标场景（本地开发调试的典型痛点）：

1. **手机 App / 模拟器联调** —— 真机、雷电/MuMu 等模拟器流量观测
2. **走系统代理的桌面应用与小程序** —— PC 端应用随系统代理联网（配合内置系统代理开关一键接管），抓小程序及业务后端
3. **CEF/Electron 桌面端** —— 目标应用以 `--proxy-server=127.0.0.1:9090` 启动后配合抓包
4. **后端 API 联调** —— HTTP 接口的请求/响应核对（Headers、JSON、Token）

## 二、核心原理（MITM 中间人）

抓包的本质：让客户端流量经过本机代理，代理用**自签 CA 动态签发假证书**完成双向 TLS，从而看到明文。

```
 客户端(App/浏览器)                Prism 代理                     真实服务器
      │                              │                              │
 1    │──── CONNECT api.x.com:443 ───▶│                              │
 2    │◀───── 200 Connection ─────────│                              │
      │                              │──── DNS + TCP ──────────────▶│
 3    │◀─ TLS握手(假证书:api.x.com) ──│◀──── TLS握手(真证书验证) ────│
 4    │                              │   [双向隧道内均为明文]          │
 5    │──── GET /api/... (明文) ─────▶│─── GET /api/... ────────────▶│
 6    │◀─── 200 JSON (明文) ──────────│◀─── 200 JSON ────────────────│
      │                              │                              │
      │                    5/6 之间：解析、记录、存储 Flow
```

关键点：

- **HTTP 明文流量**：直接解析 absolute-form 请求转发，无需解密
- **HTTPS**：`CONNECT` 后按 SNI/目标主机动态签发叶子证书（由本地 Prism Root CA 签发），客户端须**信任该 CA**
- **客户端不信任 CA 时**：表现为握手失败/CONNECT 隧道透传 —— 与 Reqable/Fiddler 行为一致

职责分层：

- **Go 负责一切网络与数据处理**（性能、并发、TLS），前端只做展示

## 四、模块设计

### 4.1 proxy — 代理引擎

- 监听生命周期管理（启动/停止/端口冲突检测）；**默认绑定 `127.0.0.1`**，仅在手机抓包向导中显式开启局域网绑定（0.0.0.0 + 防火墙放行引导），避免默认在 LAN 上形成开放匿名代理
- **明文 HTTP**：解析 `GET http://host/path HTTP/1.1` 绝对形式请求，改写后转发
- **内置页面拦截**：发往本监听端口的 origin-form 请求（如 `/ca` 证书下载页）由本地应答，不进入转发逻辑（见 4.2）
- **上游转发**：`http.Transport{ DisableCompression: true }`，原样透传客户端 `Accept-Encoding` —— 保证 store 中 `RawBody` 为线上真实字节，解压只发生在展示层。若不禁用，Transport 会透明解压 gzip 并剥离 `Content-Encoding`，导致 raw/Hex 视图与实际传输不符
- **CONNECT 隧道**：
  - 命中解密规则（默认全部，支持域名白/黑名单，见 4.7）→ 进入 MITM
  - 不解密（如被排除域名）→ 透明字节转发，仅记录元信息（host、字节数）
- **WebSocket**：MITM 后识别 `Upgrade: websocket`，记录握手首部，后续帧字节透传（MVP 不解帧，V2 再做帧解析）
  - 实现路径：`http.Transport.RoundTrip` **无法接管 101 升级连接**，必须——Hijack 客户端连接 → 向上游手动写请求行/首部 → 校验上游 `101 Switching Protocols` 并回写客户端 → 双向 `io.Copy` 字节透传
- **错误流**：上游连接失败/DNS 失败/超时，也要生成一条带 `error` 的 Flow 记录，不能静默吞掉
- **流式转发与捕获（tee 语义）**：请求/响应体边转发边捕获 —— 转发始终为完整流，store 仅保留阈值内字节并打截断标；大上传/大下载/SSE 不阻塞、不撑爆内存
- 客户端侧 ALPN 仅提供 `http/1.1`（简化多路复用处理）；上游由 `http.Transport` 协商 h2，响应统一转回 HTTP/1.1
  - 实现注意：为记录上游真实证书链需自定义 `TLSClientConfig`，而 Go 一旦自定义该字段便**保守禁用 h2**，必须显式 `ForceAttemptHTTP2: true`，否则上游永远只走 HTTP/1.1

### 4.2 cert — 证书中心

- 首次启动生成 **Prism Root CA**（RSA-2048，有效期 10 年），持久化到用户数据目录；私钥文件 ACL 限当前用户（可选 DPAPI 加密）
- `tls.Config.GetCertificate` 回调：按 host 动态签发叶子证书（ECDSA P-256，有效期 ≤1 年；正确填 SAN：DNS / IP），LRU 缓存 + singleflight 防同域名并发握手重复签发
- CA 分发三通道：
  1. UI 内一键「安装到 Windows 系统证书库」（`certutil -addstore -f Root`，或 Windows API）
  2. 内置下载页：手机访问 `http://<电脑IP>:9090/ca` 下载 PEM/DER + 各平台安装指引
     - iOS 指引须含两步：安装描述文件 →「设置 → 通用 → 关于本机 → 证书信任设置」手动开启完全信任
  3. 导出证书文件按钮
- 捕获上游真实证书链存入 `TLSInfo`（详情面板展示，方便核对 SSL Pinning 场景）

### 4.3 capture — 会话捕获

- 结构化请求/响应：起始行、Headers、Body（区分 raw 原始字节 / 解压后内容）
- 自动解压：gzip / deflate（标准库）+ br（andybalholm/brotli）+ zstd（klauspost/compress）—— zstd 为必选项：透传 `Accept-Encoding` 后现代浏览器/CDN 会返回 zstd，缺它则高频落入 Hex 兜底
- Content-Type 嗅探分类：json / form / image / text / binary / event-stream，前端按类别渲染
- 计时（DNS、连接、TLS、首字节、总耗时，经 `httptrace` 采集；走上游代理时 DNS 计时针对上游主机）与流量尺寸统计

### 4.4 store — 流量存储

- **内存环形缓冲**：默认保留 2000 条或 256MB 内存预算（可配置），超限淘汰最旧；内存预算按 body 实际字节统计，而非仅按条数
- 单 body 截断阈值默认 2MB（截断打标，不撑爆内存）
- ID 索引 O(1) 查详情；事件总线向 UI 增量推送新 Flow 元数据
- **事件节流**：`flow:new` / `flow:update` 批量合帧推送（约 50ms 窗口），避免高频请求下 Wails IPC 成为瓶颈
- **淘汰通知**：环形缓冲淘汰时推送 `flow:evict`（携带被淘汰 ID 列表），前端同步移除；详情接口对已被淘汰的 ID 返回明确"已淘汰"错误，UI 降级提示
- 落盘/会话持久化（打开历史抓包文件）→ **V1.1**

### 4.5 upstream — 出口策略

- 直连（默认）
- 手动上游代理（HTTP 代理）—— 解决「开着 Clash 抓不到」的经典冲突
  - 能力边界（MVP）：仅 HTTP 代理（CONNECT 级联由 `http.Transport` ProxyURL 处理）、无代理认证、无 SOCKS5；Clash 混合端口场景够用，SOCKS5/认证放 V1.1+ 评估
- 系统代理检测（Windows 下读注册表而非环境变量）+ 明显的 UI 提示
- **自身环路防护**：本工具接管系统代理后，检测结果须识别"指向自身端口"并排除；选择"跟随系统代理"时同样跳过自身，避免回环

### 4.6 sysproxy — 系统代理开关

- 一键设置/关闭 Windows 系统代理：写注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`（`ProxyEnable` / `ProxyServer` / `ProxyOverride`），调 `InternetSetOption`（39 SETTINGS_CHANGED + 37 REFRESH）广播刷新，新启动的浏览器/应用即时生效
  - 注意：广播对**已运行、缓存了代理配置的部分桌面应用生效不完全，常需重启该应用** —— UI 文案为"已接管，部分应用需重启后生效"，不做过度承诺
  - **ProxyOverride 合并语义（硬要求）**：接管时把**内置绕过常量**与用户已有 `ProxyOverride` 合并去重（前缀保留 `<-loopback>`），**绝不覆盖**；恢复时还原备份原值。绕过语义：分号分隔，裸域名同时匹配自身与全部子域（如 `trae.cn` 覆盖 `api.trae.cn`）
  - **内置绕过列表**（开发工具自身/常见 AI 与本机服务，治"代理崩溃残留致断网"）：Trae 与字节/火山系 `trae.cn / trae.ai / trae.com / trae.com.cn / trae.volces.com / zijieapi.com / volces.com / volcengine.com / volcengineapi.com / bytedance.com / bytedance.net / byted.org / byteoversea.com / byteintl.net / bytepluses.com / snssdk.com / doubao.com / byted-static.com / tiktokcdn.com`；以及 `localhost / 127.0.0.1 / <-loopback>`。列表可在设置页增删并持久化。原理：绕过在客户端侧直接拨号、代理收不到 CONNECT，**比代理内解密黑名单更靠前**——代理进程死掉、注册表残留时这些域名仍通
- 接管前记录原始代理配置（ProxyEnable / ProxyServer / ProxyOverride / AutoConfigURL）**并持久化到磁盘**，退出/关闭开关时**按原值恢复**，避免"关工具即断网"
- **崩溃自愈**：进程崩溃/被强杀导致注册表残留指向已死端口时，下次启动自检 —— 系统代理指向本工具端口且非本次会话设置 → 自动恢复原值；卸载时同样清理
- 状态检测：系统代理已指向本工具 → UI 显示"已接管"；指向其他代理（Clash 等）→ 明显冲突提示，由用户决定是否覆盖
- 价值：闭环「桌面应用/小程序随系统代理联网」场景（第一章场景 2），免去手动改 Windows 设置

### 4.7 rules — 规则控制

三层规则体系（均可配并持久化，与 UI 展示过滤相互独立）。**匹配语义：每层规则为有序列表，自上而下首条命中即生效；全部未命中走默认动作**（捕获默认 include、解密默认 MITM、进程默认 include）：

- **捕获规则 captureRules**：决定 Flow 是否进入 store —— 匹配维度：域名通配符（`*.example.com`）、URL 正则、请求方法；动作 include / exclude（exclude 正常转发但不记录）。用途：屏蔽遥测、心跳、静态资源噪声
- **解密规则 decryptRules**：域名白/黑名单，决定 CONNECT 后 MITM 还是透传（即 4.1 的解密规则）；列表 UI 提供"一键排除此域名"快捷操作（应对 SSL Pinning 导致的握手失败）
- **进程规则 processRules**：按进程名 include / exclude（如「只抓目标应用.exe」「排除 chrome.exe」）

进程识别原理与边界：

- 本机连接源为 `127.0.0.1:随机端口`，accept 时通过 Windows API `GetExtendedTcpTable` 将源端口即时映射到 PID → 进程名/路径：
  - 必须同时查询 IPv4 与 IPv6（`AF_INET` / `AF_INET6`）两张表，否则漏掉 `::1` 回环连接
  - 临时端口秒级复用，**不做长期缓存**，仅在 accept 时即时查询（如需缓存须极短 TTL + 四元组匹配），避免误标
  - 权限边界：目标进程以管理员运行而本工具未提权时取进程路径会失败 —— 降级显示（有 PID、名称置灰），UI 提供"以管理员身份重启"提示
- **仅本机有效**：雷电（`dnplayer.exe`）/ MuMu 等模拟器流量经主机 NAT 发出，主机侧大概率可映射到模拟器进程 —— **此假设列为 M1 硬性退出条件实测验证，若不可归因则进程规则整体降级**；手机真机经 LAN 连入无法识别进程，按 `ClientAddr` 区分设备
- 不引入驱动/WFP 拦截（Reqable 的做法），超出 MVP 体量

### 4.8 Wails Bindings（控制面接口）


## 五、数据模型

```go
type Flow struct {
    ID         string        // ULID
    State      FlowState     // pending | streaming | done | error（进行中请求/SSE/WebSocket 隧道必须有状态机）
    StartedAt  time.Time
    DurationMS int64
    ClientAddr string        // 谁发的（区分手机/本机）
    ServerAddr string        // 上游真实 IP:Port（排障必需）
    Process    *ProcessInfo  // 本机连接的进程信息，远程设备为 nil
    Scheme     string        // http | https | tunnel | websocket
    Method     string
    Host       string
    Path       string        // 含 query
    Status     int
    Error      string        // 非空即错误流
    Timing     *Timing       // DNS/连接/TLS/首字节/总耗时（httptrace 采集）
    BytesUp    int64         // 隧道/WS 模式下的字节计数（无 Message 时统计）
    BytesDown  int64
    Request    *Message
    Response   *Message
    TLS        *TLSInfo      // 版本/密码套件/SNI/上游真实证书链
}

type Message struct {
    StartLine  string        // 请求行/状态行原文
    Headers    http.Header
    RawBody    []byte        // 原始（可能压缩）字节，超阈值截断
    Body       []byte        // 解压后内容，超阈值截断
    Size       int64         // 真实完整大小（截断前）
    Truncated  bool
    ContentType string
    ContentEncoding string   // gzip | deflate | br | zstd | ""
    Kind       string        // json | image | form | text | binary | eventstream
}

type ProcessInfo struct {
    PID  uint32
    Name string            // 如 dnplayer.exe
    Path string            // 可执行文件全路径（用于区分同名进程）
}
```

## 六、MVP 功能清单与验收标准

| # | 功能 | 验收标准 | 里程碑 |
|---|------|----------|--------|
| 1 | HTTP 明文代理 | `curl -x 127.0.0.1:9090 http://example.com` 正常返回并记录 | M1 |
| 2 | CONNECT 透传隧道 | 不解密模式下 HTTPS 站点可正常访问（字节转发） | M1 |
| 3 | CA 生成与动态签发 | `curl -x ... -k https://...` 能看到明文请求 | M2 |
| 4 | HTTPS MITM 解密 | 浏览器/手机安装 CA 后访问 HTTPS 站点，明文完整捕获 | M2 |
| 5 | 证书下载页 + Windows 一键安装 | 手机访问 `http://ip:9090/ca` 可下载并按指引安装 | M2 |
| 6 | 流量实时列表 | 请求实时滚动显示：方法/域名/路径/状态/耗时/大小，虚拟滚动 2000 条不卡 | M3 |
| 7 | 详情面板 | Headers 表格、Body 多视图（JSON 树/文本/图片预览/Hex/表单）、TLS 信息、进程信息 | M3 |
| 8 | 过滤与搜索 | 按域名/方法/状态码/关键字实时过滤，正则可选 | M4 |
| 9 | 设置与规则 | 端口/绑定地址/上游代理/解密名单/捕获规则/进程过滤可配并持久化 | M4 |
| 10 | 系统代理开关 | 一键接管/恢复 Windows 系统代理，新启动应用即时生效（已运行应用重启后生效，见 4.6）；退出/崩溃均按原值恢复 | M4 |
| 11 | 打包分发 | `wails build` 产出单 exe，干净 Win11 机器可用 | M4 |
| 12 | 流式与大文件 | SSE 长连接实时追加展示不阻塞；50MB 下载边转发边捕获，进程内存稳定在预算内 | M3 |
| 13 | 代理崩溃自愈 | 接管系统代理后强杀进程，重启工具自动恢复原代理设置，不造成"断网" | M4 |

**明确不在 MVP 范围**（放 V1.1+）：Rewrite 重写、断点拦截、Map Local、弱网模拟、请求重发、cURL 导出、HAR 导入导出、WebSocket 解帧、HTTP/3。

## 七、关键技术难点与对策

| 难点 | 对策 |
|------|------|
| HTTP/2 多路复用 MITM 复杂 | 客户端侧 ALPN 只给 `http/1.1`，上游 h2 交给 `http.Transport`；V2 再评估客户端侧 h2 |
| QUIC / HTTP3 抓不到 | UDP 无法走 HTTP 代理，客户端自动回退 TCP（与 Reqable 一致）；文档注明"Chrome 需禁用 QUIC" |
| App 证书校验（SSL Pinning） | 工具层无解，标记已知限制（与所有代理工具一致） |
| brotli 响应解压 | 引入 `andybalholm/brotli`，解压失败保留 raw + Hex 视图兜底 |
| 与 Clash 等 VPN 冲突 | upstream 模块支持上游代理 + 启动时检测系统代理并 UI 提醒 |
| Windows 防火墙拦截 | 默认仅绑定 127.0.0.1 无需放行；开启局域网绑定时（手机抓包向导）引导防火墙放行 |
| 默认绑定 0.0.0.0 形成 LAN 开放代理 | 默认绑定 127.0.0.1，局域网绑定为显式开启项（见 4.1） |
| 工具崩溃致系统代理残留断网 | 原始配置落盘 + 启动自检自愈（见 4.6）；**ProxyOverride 内置绕过列表**让 Trae/AI 等关键域名在代理死亡残留时仍直连免疫 |
| WebView2 运行时缺失（Win10 LTSC/精简版） | 启动检测 + 引导下载运行时；安装包内置 bootstrapper |
| exe 未签名触发 SmartScreen / 杀软误报 | 「装根证书 + 改注册表代理」属典型恶意软件行为特征（代理工具共性高发问题），预留代码签名成本与误报申诉预案 |
| 大响应/内存膨胀 | body 截断阈值 + 环形缓冲淘汰策略 |
| Windows 系统证书安装 | `certutil -addstore -f Root`（需管理员，UI 明确提示）；失败给手动指引 |
| 端口被占 | 启动时检测并给出明确错误与换端口建议 |

## 十、里程碑规划

```
M1 代理引擎骨架 ──▶ M2 MITM 解密 ──▶ M3 UI 流量面板 ──▶ M4 过滤/设置/打包 = MVP
```

- **M1**：代理引擎 —— 明文 HTTP 代理 + CONNECT 透传 + 错误记录（命令行/日志验证）
  - 硬性退出条件补充：雷电/MuMu 模拟器流量**进程归因实测**（`GetExtendedTcpTable` 能否映射到模拟器进程），结论决定 4.7 进程规则的设计走向
- **M2**：证书中心 + HTTPS MITM —— curl 与浏览器全链路明文捕获
  - **关键路径**：MITM 正确性 edge case 集中于此（chunked、100-continue、keep-alive 复用、WS 升级、流式响应），预留最多调试余量
  - 里程碑末做**真实场景冒烟**：桌面应用（系统代理）+ 雷电模拟器 + CEF/Electron 桌面端（`--proxy-server`）三场景各跑通一次，尽早暴露假设问题（而非等到 M4）
- **M3**：Wails 壳 + 流量列表 + 详情面板（JSON/文本/图片/Hex）
- **M4**：过滤搜索、规则控制（捕获/解密/进程）、设置持久化、上游代理、系统代理开关、打包发布 → **MVP 完成**

**测试策略**：以 curl 用例做代理正确性单测（chunked、100-continue、keep-alive、trailer、大 body 截断）；里程碑验收跑集成矩阵 —— 客户端（curl / 浏览器 / 桌面应用 / 雷电 / MuMu / 手机真机）× 流量类型（HTTP / HTTPS / WebSocket / SSE / 大文件）。

**V1.1**：会话落盘/打开、cURL 复制导出、HAR 导入导出
**V2**：Rewrite 重写、断点拦截、Map Local、弱网模拟、WebSocket 解帧

## 十一、风险与限制声明（写进产品文档）

1. App 启用 SSL Pinning 时无法解密（所有代理工具的共性限制）
2. HTTP/3 (QUIC) 不支持，需让客户端回退 TCP（浏览器禁用 QUIC）
3. Android 7+ 用户 CA 对 App 默认不生效，需 debug 包配置 `networkSecurityConfig` 或 Root 写系统证书
4. CA 私钥在本机，仅限**开发调试**用途，勿在生产环境信任
5. 进程识别仅对本机（含模拟器）有效，手机真机按设备 IP 区分
6. 部分安全软件可能将「安装根证书 + 修改系统代理」判定为高风险行为（代理工具共性），需在安全软件中添加信任；exe 未签名首次运行会触发 SmartScreen，需"仍要运行"

## 十二、与 Reqable 的 MVP 对比

| 能力 | Reqable | Prism MVP |
|------|---------|-----------|
| HTTP/HTTPS MITM | ✅ | ✅ |
| HTTP/2（上游） | ✅ | ✅（客户端侧 1.1） |
| HTTP/3 | 部分 | ❌ |
| 流量列表/详情/过滤 | ✅ | ✅ |
| WebSocket 解帧 | ✅ | ❌（透传） |
| Rewrite/断点/弱网 | ✅ | ❌（V2） |
| 跨平台 | Win/Mac/Linux/iOS/Android | Windows |
| 定制化 | 闭源 | **完全开源可控，可按自身调试工作流定制** |

**自研必要性补充论证（vs 开源 mitmproxy 等）**：本工具的三个核心差异点均为 Reqable / mitmproxy 不具备或难以定制的 —— ① sysproxy 一键接管/恢复闭环（随系统代理联网的桌面应用零配置）；② 进程级过滤（只抓指定目标进程）；③ Windows 单文件开箱即用、轻量一体。mitmproxy 桌面端体验弱、Windows 支持一般，不满足「轻、快、稳」定位。

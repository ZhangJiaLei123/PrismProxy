### cURL 粘贴执行修复（2026-09-05，用户反馈）

**问题**：右键复制的 cURL 无法直接粘贴执行。M5 验收时用简单请求（header/body 无特殊字符）测通，实际抓包流量必现失败。三处根因（均针对 PowerShell）：

1. cmd 版多参数命令以 `^` 续行——PowerShell 不认 `^`（其续行符是反引号 `` ` ``），粘贴即断行报错；
2. cmd 版引号内 `\"` 转义——PowerShell 双引号串中 `"` 直接闭合字符串（`\"` 的 `\` 是普通字符），含引号的 header/JSON body 解析错乱；
3. PowerShell 双引号串内 `$var` 会被变量展开、`` ` `` 是转义符，原实现完全未处理。

**修复**（internal/capture/curl.go + FlowList.vue）：
- `quoteCmd` 改 `\"` → `""`：cmd 侧相邻双引号只翻转引号状态两次（无害），curl.exe 的 MSVC CRT 把引号内 `""` 还原为字面 `"`；`""` 恰好也是 PowerShell 的字面引号转义——**cmd 与 PowerShell 双兼容**；
- 新增 `ShellPowerShell`（`BuildCurl(id, "powershell")`）：转义 `` ` ``→`` `` ``、`"`→`""`、`$`→`` `$ ``；显式 `curl.exe`（规避 PS 5.1 的 Invoke-WebRequest 别名）；
- 右键菜单拆为三项：复制 cURL (cmd) / (PowerShell) / (bash / Git Bash)；
- **2026-09-05 追加：三版全部改单行输出**（Chrome DevTools 导出 curl 的标准形态）——续行符（cmd `^` / PS `` ` `` / bash `\`）在错误终端粘贴必炸且各不相同，单行彻底规避；原先 `-H` 与值分行多行排版同样废除；
- 已知残留（可接受）：cmd 交互模式对引号内 `%var%` 仍做变量展开，无法完美转义；孤立的 `%xx`（URL 编码如 %20）不构成变量引用不受影响。

**排查记录（2026-09-05 用户二次反馈"bash 版还是无法粘贴使用"）**：用户贴回的内容中 URL 两侧带反引号（`` '`http://...' ``），临时复现测试构造同款流逐字节比对——**代码输出无反引号、与用户内容除反引号外逐行一致**，断定反引号是粘贴到聊天框时的 markdown 渲染产物，非程序生成；同时用户贴的多行形态暴露了续行符这一真实兼容性隐患 → 落地单行化。**三版命令语法互不兼容是本质特性**（bash 单引号版粘贴到 PowerShell 会报语法错误，反之亦然），必须按目标终端选对应菜单项；另注意 Git for Windows 精简版无 curl（bash 版会 command not found）。

**验证**：go test 全绿（curl_test 新增 PowerShell 用例锁字节级输出：`""`/`` `$ ``/`` `` ``/续行符）；PowerShell 5.1 实测 `""`/`` `$ ``/`` `` ``/JSON body 转义语义均还原为期望参数；vite build + wails build 通过。GUI 端到端（右键复制→粘贴执行）待用户日常使用确认。

### M7 代码审查修复记录（2026-09-07）

首轮代码审查（2 个独立子代理交叉验证）发现并修复 5 个问题，其中 2 个严重：

- **【严重·死锁，已运行时复现】applyPersist 重入 pmu 自死锁**：原 applyPersist 全程持 `a.pmu` 又调 `st.Add` 补载历史，而 `Store.emit` 同步回调订阅者 `onPersistEvent` 也要取 pmu（不可重入）→ 同一 goroutine 二次加锁永久挂死。触发条件：持久化运行中 + 历史流不在内存（清空列表/被环形淘汰）后保存任意设置即必现，且连带 UI 事件分发全卡死。修复：pmu 仅保护 writer 指针读写，订阅与历史补载 `st.Add` 一律移到锁外（历史流 Source=history 被 onPersistEvent 跳过，无回写）；回归测试 `TestPersistReapplyNoDeadlock`（关→开重连补载路径）。
- **【严重·保留策略反转】maxMB 上限失效且触阈值清空全部历史**：DSN 未设 auto_vacuum（默认 NONE）也从不 VACUUM，SQLite 删除行不缩小主 .db 文件，`wal_checkpoint(TRUNCATE)` 只截断 WAL；导致 `enforceSize` 的 `for dbSize()>maxBytes` 永不达标、一路删到 flows 表空（默认 500MB 后每 10 分钟全清）。修复：DSN 加 `auto_vacuum(INCREMENTAL)` + migrate 对既有库一次性 `VACUUM` 迁移；**WAL 模式下收缩顺序必须是 DELETE → `PRAGMA incremental_vacuum`（空闲页释放写入 WAL）→ `wal_checkpoint(TRUNCATE)`（并入主库并截断 WAL）**，顺序反了主文件不缩反增；enforceSize 改分批（chunk=64）删除+收缩。回归测试实测峰值 4.16MB → 清理后 28KB。
- **【次要】applyPersist 无条件重开 writer**：保存任意无关设置都 Close→Open→LoadRecent 全量重扫。修复：新增 `Writer.Path()`/`UpdateRetention()`，同 DB 路径仅热更新 retainDays/maxMB 不重连（`TestPersistRetentionUpdateNoReopen` 验证复用同一实例）；路径变化/由关到开才重连。
- **【次要】每条流 body 双重深拷贝**：Enqueue 已深拷贝（热路径隔离，必要），marshalFlow 出队后又 cloneFlow（单消费者只读，冗余）。修复：marshalFlow 改浅拷贝 Flow + 浅拷贝 Request/Response 结构体置 Body=nil，不再复制 Header map/body 字节。
- **【次要】历史正文回查失败静默空白**：持久化关闭后历史流详情显示 N 字节却正文空白、DB 出错被静默。修复：新增 `loadHistBody` 统一回查，失败/关闭时 `log.Printf` 并经 BodyPayload.DecodeErr / 原文【…】明确提示；删除无调用方的死代码 `HasBody`。

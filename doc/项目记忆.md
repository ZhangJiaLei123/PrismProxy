## 项目定位

- **PrismProxy（棱镜）**：Windows 桌面 HTTP(S) 抓包工具，MITM 代理 + 按进程名归因流量；独立开源工具，定位与文档均不绑定任何特定业务。
- 核心场景：抓取**模拟器（雷电/MuMu）内 App**、真机与 PC 软件的 HTTPS 流量。
- 方案文档：[方案.md](./方案.md)（已完成全面审计并修订，作为开发依据规范）。
- **文档位置（2026-09-04 起）**：三份 md 文档统一移至 [`doc/`](./) 目录，文档内相对链接仍互相有效。
- **Git 仓库（2026-09-04 开源）**：`https://github.com/ZhangJiaLei123/PrismProxy.git`（main 分支）。初始提交含 M1-M3 代码 + `domains/` + `doc/`；`.gitignore` 排除 `build/bin/`、`frontend/dist/`、`frontend/node_modules/`、`*.exe`、`frontend/package.json.md5`。文档已去除业务绑定（修车助手/F6 等第三方描述）。**仓库公开，后续写文档/commit/注释时勿引入任何具体业务方名称，保持独立开源工具定位。**

## 技术栈

- 代理引擎：**Go**（标准库为主）
- 桌面壳：Wails v2 + Vue 3 / TS + Naive UI + @vueuse/core（虚拟滚动）
- 平台：Windows 优先（WebView2 运行时）

## 关键技术决策与陷阱（审计结论，必须遵守）

1. **ForceAttemptHTTP2 陷阱**：为记录上游真实证书链需自定义 `TLSClientConfig`，而 Go 一旦自定义该字段便保守禁用 h2 —— 必须显式 `ForceAttemptHTTP2: true`。
2. **流式捕获 tee 语义**：边转发边捕获，Flow 状态机 `pending/streaming/done/error`；WebSocket/101 升级连接 `http.Transport` 无法接管，必须 Hijack。
3. **默认绑定 127.0.0.1**：避免 LAN 开放匿名代理；局域网绑定是显式开启项。
4. **PID 进程映射**：`GetExtendedTcpTable` 须同时查 AF_INET + AF_INET6 两表；accept 时即时查询（不做长期缓存）；目标进程权限不足时取路径失败 → 降级显示 + 提权提示。
5. **解压**：gzip/deflate（标准库）+ br（andybalholm/brotli）+ **zstd（klauspost/compress）**（透传 Accept-Encoding 后 CDN 会返回 zstd）。
6. **系统代理**：注册表真实路径是 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`（**方案文档里的 `HKCU\Internet Settings` 是简写，`reg query` 必须用完整路径否则报"找不到项"**；PowerShell 的 `HKCU:\` PSDrive 有时也异常，稳妥用 .NET `[Microsoft.Win32.Registry]::CurrentUser.OpenSubKey(...)`）；`InternetSetOption` 广播 39(SETTINGS_CHANGED)+37(REFRESH)；原始配置落盘 `%APPDATA%/PrismProxy/` + 崩溃自愈；已运行的部分桌面应用进程（如 Trae）生效不完全常需重启（新启动进程立即生效，curl 实测即时）。
   - **ProxyOverride 绕过语义**：分号分隔；**裸域名同时匹配自身与全部子域**（`trae.cn` 覆盖 `api.trae.cn`/`x.trae.cn`）；`<-loopback>` 绕过本地回环。绕过发生在客户端侧（WinINET/Chromium 直接拨号，**代理根本收不到 CONNECT**），比代理内"解密黑名单"更靠前——是"代理进程死了、注册表残留"断网场景的**系统级免疫**。
   - **已内置的开发机绕过列表（2026-09-03 应用）**：`trae.cn / trae.ai / trae.com / trae.com.cn / trae.volces.com / zijieapi.com / volces.com / volcengine.com / volcengineapi.com / bytedance.com / bytedance.net / byted.org / byteoversea.com / byteintl.net / bytepluses.com / snssdk.com / doubao.com / byted-static.com / tiktokcdn.com`（备份 `%APPDATA%\PrismProxy\proxyoverride-backup.txt`，原值 `<-loopback>;api.trae.cn;mcs.zijieapi.com`）。Trae CN 域名事实取自其 `resources/app/out/main.js`：API/遥测走 `*.trae.volces.com`、`mcs/mon.zijieapi.com`、`gator/tab/apmplus.volces.com`、`abtestvm.bytedance.com`，前端 CDN `*.byted-static.com`。
   - **M4 sysproxy 模块硬要求**：接管时**合并去重** ProxyOverride（内置绕过列表常量 + 用户已有值，前缀保留 `<-loopback>`），**绝不覆盖**；恢复时还原备份原值。
   - **退出清理三场景（2026-09-05 补齐关机场景）**：①关窗口/Alt+F4 → Wails `OnShutdown`（app.shutdown）；②**系统关机/注销/重启 → Wails v2.15 主窗口 winc WndProc 只处理 WM_CLOSE/WM_DESTROY，不处理 WM_QUERYENDSESSION/WM_ENDSESSION（源码已核实），OnShutdown 不触发**——自建隐藏顶层窗口接收（`session_windows.go`：独立 goroutine + `runtime.LockOSThread` + RegisterClassExW/CreateWindowExW/GetMessage 消息循环；**必须普通顶层隐藏窗口，HWND_MESSAGE message-only 窗口收不到 ENDSESSION 广播**），WM_QUERYENDSESSION 返回 1、WM_ENDSESSION(wParam=TRUE) 同步还原；③`taskkill /F`/强杀/崩溃 → 任何程序无法即时处理，下次启动 SelfHeal 兜底。还原逻辑抽为 `App.restoreSystemProxy()`（Status==StateOn 才 Disable，幂等），shutdown 与会话回调共用；非 Windows 有 `session_other.go` 空桩。headless 模式不管系统代理无需处理。
7. **CA**：私钥 ACL 限当前用户（可选 DPAPI）；叶子证书 ECDSA P-256、有效期 ≤1 年、LRU 缓存 + singleflight。
8. **规则引擎**：捕获/解密/进程三层，有序列表首条命中生效 + 默认动作。
9. **内存**：环形缓冲 2000 条/256MB 按 body 实际字节统计；body 2MB 截断；事件批量节流 ~50ms + `flow:evict` 淘汰通知。

## V1.x 关键决策（2026-09-04 规划，M5-M8 开发时必读）

1. **需求拆分**：M5=右键复制 URL/cURL + 详情复制 + 列表置顶 + **快捷忽略域名/进程** + 规则导入导出；M6=调试重发 Composer；M7=SQLite 持久化；M8=AI CLI 控制。详见方案 §4.9-4.12。
2. **cURL 生成在 Go 侧**（BuildCurl binding，2026-09-05 修订为三 shell + 单行输出）：**单行输出**（Chrome DevTools 标准形态，杜绝 `^`/`` ` ``/`\` 续行符跨终端粘贴兼容问题）。cmd 与 PowerShell 版双引号包裹、引号内 `""` 转义（MSVC CRT 与 PS 均还原为字面 `"`，**cmd/PS 双兼容**；cmd 交互模式 `%var%` 无法完美转义属已知残留）；PowerShell 版 `` ` ``→`` `` ``、`$`→`` `$ `` 必须转义（PS 双引号串内 $var 会展开、` 是转义符）；bash 版单引号 `'\''`；三者均显式 `curl.exe`（规避 PS 5.1 别名）。body 文本 ≤64KB 内联，二进制不内联。**教训：① `\"` 转义只在 cmd 有效，PowerShell 中 `"` 直接闭合字符串；跨 shell 引用规则差异必须逐字实测，不能用简单请求（无特殊字符）代替验收。② 三版语法互不兼容是本质特性（bash 版贴 PowerShell 报语法错误，反之亦然），须按目标终端选菜单项；Git for Windows 精简版无 curl。③ 用户贴回的"命令内容"可能被聊天框 markdown 渲染篡改（如 URL 两侧加反引号）——排查先本地复现逐字节比对，勿直接采信。**
3. **置顶语义**：Flow.Pinned——固定顶部展示、不参与环形淘汰、Clear 保留、上限 200、会话内状态不持久化。
4. **调试重发（M6 已实施，2026-09-05）**：独立 http.Client **直连防回环**（跟随上游代理设置）；重发 Flow `Source="composer"` 入 store 可迭代；HTTP/1.1 only。实施细节见下文「M6 关键认知」节。
5. **SQLite 选型 `modernc.org/sqlite` v1.58.0**（纯 Go 无 CGO，M7 已实施 2026-09-07）——`mattn/go-sqlite3` 依赖 CGO/mingw 破坏单 exe 构建链，**禁用**。DSN `?_pragma=busy_timeout(5000)&_pragma=journal_mode(WAL)&_pragma=synchronous(NORMAL)` + `SetMaxOpenConns(1)` 单写连接；构建 `CGO_ENABLED=0 wails build` 通过（exe 20.5MB）。持久化默认关闭；异步队列批量写，队列满丢弃，绝不阻塞代理热路径。DB 落便携目录 `config/prism.db`（非旧规划 %APPDATA%）。实施细节见下文「M7 关键认知」节。
6. **AI CLI 形态（M8 已实施，2026-09-05）**：同 exe 子命令 `PrismProxy.exe cli <cmd>` + 本地控制 API（127.0.0.1:9595，独立于代理端口 9090）+ token 认证；默认 JSON 输出（--pretty 缩进）；与 Wails Bindings 共用内部服务层。**实施落点与规划的两处修订**：① token 与监听地址落盘 **`config/ctl-endpoint.json`（{addr,token}，便携模式与 settings.json 同目录）**，不是旧规划的 `%APPDATA%/PrismProxy/cli-token`；原子写 + 0600 + Windows icacls 限当前用户，实例 Close 时删文件（强杀残留→cli 连接拒绝友好提示，下次启动覆盖）；② 架构上 ctlapi 包定义 `Service` 接口，main 包用 **`ctlService` 适配器包装 `*App`** 实现——App 已有同名 Wails binding（GetSettings/ListFlows/ClearFlows/GetFlowBody 等），直接在 App 上加方法会冲突，适配器是唯一干净解。命令集：status / flows list|get|clear（--filter/--limit/--body）/ rules list|ignore host|process|group enable|disable|decrypt mitm|bypass / sysproxy status|on|off / settings get|set（读-改-写）/ ui clear|settings [tab]。**UI 控制**：数据级动作（ui clear 清 store）GUI 经既有 flow:evict 自动同步、headless 也执行（返回 {cleared,ui}）；纯界面动作（ui settings 打开/切设置面板 tab）走 Wails `EventsEmit("ui:open-settings", tab)` → 前端 EventsOn 执行 + WindowUnminimise，headless 返回 {"ui":false} 不报错；tab 白名单 general/network/decrypt/capture/domains，非法 400。
7. **规则导入导出**：JSON 含 version；文件/URL 两种来源；整体替换 + schema 校验；域名组引用缺失时提示（导出可内嵌组清单）；domains/ txt 仍是域名唯一事实源。
8. **快捷忽略（M5 已实施，落点=双内置黑名单组）**：域名列→忽略自身+全部子域（裸域名语义）写入 `_quick_ignore_hosts`（名称"快捷忽略-域名"，hosts 维度）、进程列→按进程名写入 `_quick_ignore_procs`（名称"快捷忽略-进程"，processes 维度）；两组均 blacklist/enabled，**组间 OR 各管一维**。**必须双组不能单组**：组内维度 AND——若 hosts 与 processes 混在同一 `_quick_ignore` 组，"忽略域名"加的 host 会与"忽略进程"加的 proc 互相收窄（host 命中但 proc 不命中→整条不屏蔽），两个快捷动作彼此失效；旧混合组由 `settings.Migrate`（splitQuickIgnoreGroup）启动时自动按维度拆分、幂等可重入。幂等防重复；只影响后续流量存量不删；热更新+落盘 settings.json；设置页双组卡片与普通组同构（可见/可删/可开关）。Binding：`AddQuickIgnore(target, value)`。
9. **过滤规则组改造（2026-09-04 设计定稿 + 审计修订 + 同日实施完成 = M4.6）**：黑名单/白名单两模式（默认黑名单）+ 多规则组。**详细设计见 [规则设计.md](./规则设计.md)（唯一事实源）**，要点：`FilterGroup{id,name,enabled,mode,hosts,paths,processes}` 替换 captureRules/processRules（自动迁移、迁移幂等、迁移组按黑白区分命名，decryptRules 不动）；组内维度 AND、同维度多条目 OR、组间 OR、deny-override（黑名单恒优先，无白名单组默认全显示）；path glob（`*`跨`/`；**无通配符=精确或子路径段边界（`/telemetry`≠`/telemetryx`），字符串比较不走正则**），只匹配 path 不含 query；引擎统一 `ShouldDisplay(host,rawURL,procName)`（nil receiver 安全返回 true）。**审计核心修订——信息缺失维度移除规则（§2.3）**：进程未知（模拟器归因 VBoxNetNAT.exe）/盲透传隧道无 path → 该维度从组约束移除，剩余约束空则组对该流不匹配（纯进程黑名单组不误伤未知进程=兼容现状；path 维度仅对 MITM/明文流量生效；纯 path 白名单组放不了隧道流是已知局限）。其余修订：@引用校验存在性但只 warning 不阻塞（Validate 返回 error+warnings）；`url.Parse` 失败降级空 path 走维度移除（不拿原始串匹配）；hosts 禁裸 `*`；NewEngine 启动失败=log warn+空引擎全放行、保存失败=拒绝保存；UI 状态条须用与引擎一致的 `isActiveWhitelist` 谓词（enabled+mode+非空）、组卡片默认折叠、未知 @引用本地即时提示 + 保存时后端 warnings 透传；已拍板：urlRe/method 直接移除、组不做排序、热更新在途流沿用现状不处理。M5 快捷忽略落点为 `_quick_ignore_hosts`/`_quick_ignore_procs` 双内置黑名单组（见上节第 8 条）。**实施备注**：`SaveSettings` 返回 `SaveSettingsResult{warnings}`（前端有 warnings 时留面板展示）；迁移在启动时 Load→Migrate→Save 即落盘；NewEngine 失败空引擎兜底全放行；Engine 保留 groups map 仅供解密层 @引用（过滤层热路径用编译期预展开）。

## M3 关键认知（GUI/验收实测）

- **store 事件语义**：`Add` 按 ID upsert——已存在则 `*old = *f` 原位更新发 "update"，否则值拷贝追加发 "new"；环形覆盖先发 "evict"。`Subscribe` 锁外回调。**字节预算（256MB）M4 已实现为配置项 maxBodyMB**；M3 内存上限 = 2000 流 × MaxBodyCapture(2MB) 兜底（压测 +79MB 驻留是设计行为非泄漏）。
- **事件合帧**：store 事件 → app.go pendUp map（入队即转 DTO 值拷贝）→ `time.AfterFunc(50ms)` flush → Wails `flow:upsert`/`flow:evict`。前端只做展示，状态全在 Go。
- **展示层解压**：`capture.DecodeBody`（gzip/deflate/br/zstd）在 GetFlowBody 调用时发生，不在捕获路径。
- **go mod tidy 陷阱**：tidy 会移除"go.mod 里声明但代码尚未 import"的依赖——先写 import 再 tidy，或 tidy 后确认依赖仍在。
- **Vue 模板字面量陷阱**：模板内 JS 模板字符串以 `}}` 结尾时会与 Vue 插值 `{{ }}` 闭合符冲突解析报错，改用字符串拼接或计算属性规避。
- **PowerShell 终端是 5.1**（$PSVersionTable 5.1.26100.9168）：**无 `ForEach-Object -Parallel`**，并行压测用 `1..N | % { Start-Job { ... } }`；**curl 是别名必须 `curl.exe`**，https 仍要 `--ssl-no-revoke`。
- **大文件测试源**：cloudflare speed 403、hetzner 502 均不可用；可用 `https://cdn.npmmirror.com/binaries/node/v22.11.0/node-v22.11.0-win-x64.zip`（34MB，30MB/s，支持 Range）。
- **Computer Use MCP 操作 WebView2 要点**：WebView 内容无 a11y 节点；click/scroll 必须传 element_id——用主树 `element_id="1"`（pane "PrismProxy"）+ x/y 坐标生效；**截图像素坐标可直接用于 click**（2026-09-04 实测命中；M3 时观察到的 +28px 纵向偏移未复现，可能源于当时窗口状态，若点击落空先换 ±28px 试）；交互前必须先 get_app_state 否则报 "No current Stable UI Tree revision"；**Ctrl+End/Ctrl+Home 可跳虚拟滚动列表底/顶**（比 pages 滚动快得多，新流 unshift 会抵消 pages 滚动）。
- **MCP 可点中 opacity:0 的按钮**：悬停才显现的 DOM 按钮（如排序按钮）在 a11y 树中可见，用坐标 click 可直接命中（opacity 不阻碍点击）；a11y 树中 button 的 val（"▲"/"▼"/"↕"）是验证按钮状态机的好抓手。
- **MCP 无法合成双击**：Computer Use 后台派发的 click（clickCount=2）合成不了 `WM_LBUTTONDBLCLK`，双击交互（如双击复制）MCP 测不了。替代：PowerShell P/Invoke user32.dll（`ClientToScreen`+`SetCursorPos`+`mouse_event(0x2/0x4)×2`）发真实输入——**必须先 `ShowWindowAsync(h,9)`+`SetForegroundWindow(h)` 并用 `GetForegroundWindow` 校验为 True**，否则点击落到上层窗口；且该法对本窗口也不稳定（WebView2 合成输入易丢双击计数），不可靠时直接请用户双击验证。
- **复制功能验证法**：`Get-Clipboard` 是最硬证据（剪贴板值精确等于单元格展示文本即通过）；toast 截图须在其存活期内抓（MCP 往返 2-4s，1.5s toast 抓不到）。

## MITM 回写 h1 组帧的两个致命协议 bug（2026-09-07 抓混合 App 定位并修复）

抓 Cordova/原生混合 App（原生侧老 xutils/com.android.okhttp on HttpURLConnection 只懂 HTTP/1.1，WebView chromium 懂 h2）时，App 弹"未连接网络/检查网络设置"且短连接 API 却 200——根因全在 MITM 客户端侧回写路径（internal/proxy/mitm.go handleMITM）。客户端侧 TLS 恒只协商 `http/1.1`（NextProtos 只有 http/1.1），但上游 `http.Transport` 开了 `ForceAttemptHTTP2`，**响应常是 h2（ProtoMajor=2、无 Content-Length）**。旧实现 `resp.Write(bw)` 有两个坑：

1. **状态行协议号穿透**：`resp.Write` 按 `resp.ProtoMajor` 写状态行，h2 响应写出非法的 `HTTP/2.0 200 OK` 给 h1 客户端 → 老 okhttp `Http1xStream.readResponse` 抛 `java.net.ProtocolException: Unexpected status line: HTTP/2.0 200 OK`，App 判无网络。**铁律：h2→h1 回写必须手写状态行恒为 `HTTP/1.1`**（flow.Response.Proto 仍记录上游真实 h2 供 UI 展示，两处分离）。
2. **流式响应不 flush，SSE/长连接被缓冲卡死**：`resp.Write(w)` 要把 body 读到 EOF 才返回，而它写的是 `bufio.Writer`（4KB），返回前从不 flush。SSE/EventSource 体永不 EOF、事件帧只有几十字节 → 全积在 bufio 缓冲里，客户端连响应头都收不到 → `EventSource`/IM SDK（如"Conn ... web"）判无网络。注意：**这种卡死的流不会落到 flows 可见态**（goroutine 阻塞在 Read，flow 停在 streaming 且不 Finish），所以"flows 里没有 SSE 长连接流"不代表 App 没发起——可能正是被代理卡死后客户端超时断开。

**修复（writeH1Response，mitm.go）**：弃用 `resp.Write`，手工按 h1 组帧——① 状态行 `HTTP/1.1 <code> <reason>`；② 分帧：上游无 Content-Length（h2 响应常态）一律转 h1 `Transfer-Encoding: chunked`，有 CL 则显式写 CL；③ 状态行+首部写完**立即 flush**（让客户端先收到头）；④ body 用 32KB buf 循环读、**每块都 flush**（chunked 每块写 `<hex>\r\n`+数据+`\r\n`，EOF 写 `0\r\n\r\n`）；⑤ HEAD/204/304 无 body 时剥掉 Transfer-Encoding/Content-Length 不发体。proxy 包既有 `streamResponse`（io.Copy 边转边捕获）理念一致，但它靠 net/http 服务器自动组帧，hijack 手写路径必须自己管分帧与 flush。

**排查 App"未连接网络"类问题的高效分诊**：`adb logcat -c` 清空 → `am force-stop` 后 `am start -n <pkg>/<入口activity>` 冷启动（入口用 `cmd package resolve-activity --brief <pkg>` 查，雷电无 monkey）→ 等 20-30s → logcat 搜 `ProtocolException|SocketTimeout|Socket closed|Exception|SSE|EventSource|Msync`，CLI 侧 `flows list` 统计 State/Host 分组、找非 done 流与 CONNECT 隧道。混合 App 优先怀疑原生老网络栈（日志 tag 如 xutils/okhttp/UpdateApkUtil 之类）与 IM/SSE 长连接。

**配套构建/验证**：改 Go 后用 `go build -trimpath -ldflags "-s -w" -o build\bin\PrismProxy.exe .`（项目根）增量编译即可，**不要用 `wails build -clean`**（清 config/ca 换 CA）；go build 保留 config。改完 `taskkill /F /IM PrismProxy.exe` + 重起 headless、`cli flows clear`、force-stop 冷启 App 复现。模拟器截图取证用 `adb shell screencap -p /sdcard/x.png` 再 `adb pull`（**PowerShell `exec-out screencap` 重定向 `>` 会把 PNG 的 \n 破坏成 \r\n，读出来"Unknown image format"**；必须走 shell 落盘 + pull）。

## M5 关键认知（GUI/验收实测，2026-09-04）

## M6 关键认知（调试重发 Composer，2026-09-05）

- **compose 旁路链路与抓包链路的口径必须对齐**：internal/compose 是独立于 proxy 的第二条"流记录"链路，凡抓包链路对 Flow 做的规范化，旁路都要照做一遍，否则同一应用内展示不一致。已踩两处：① 进程信息——抓包链路由 PID 映射填 ProcessInfo，composer 流是本进程发出，必须显式 `ProcessInfo{PID: uint32(os.Getpid()), Name: filepath.Base(exe), Path: exe}`（初版只设 Name 导致详情显示 `pid=0`）；② 逐跳首部——抓包链路 streamResponse 前 `removeHopHeaders`，composer 初版漏剥导致响应头展示 Connection/Keep-Alive；修复为 `respHopHeaders`（同 proxy.hopHeaders 九项，**响应侧保留 Content-Length**；请求侧 composerHopHeaders **含 Content-Length** 让 Transport 按 body 重算）。**以后再加旁路记录（如 M7 持久化回放、M8 CLI 造流）先核对这两份清单。**
- **防回环双保险**：Transport 默认不设 `tr.Proxy` = 直连目标（不经自身 9090）；仅当上游代理非 direct 时才设 tr.Proxy，且经 `proxy.GuardUpstreamLoop` 拦截指回本机监听口的配置（system 模式下 sysproxy.UpstreamFromSystem 自身防环：接管后注册表 ProxyServer 是自己→返回空=直连）。用户当前 upstreamMode=direct，Composer 即纯直连。
- **Transport 配置要点**：`DisableCompression: true`（保真透传，压缩交展示层 DecodeBody 统一解）；自定义 TLSClientConfig（InsecureSkipVerify 开关）后**故意不设 ForceAttemptHTTP2**——Composer 边界就是 HTTP/1.1 only；Dial 15s、Client Timeout 30s、CheckRedirect 限 10 次。
- **composer 流绕过过滤是设计不是 bug**：重发流直接 `Store.Add`（不经 Recorder.Filter/规则引擎），保证"重发必入列表可迭代"。实测佐证：用户配了快捷忽略 `_quick_ignore_procs` 含 curl.exe，经代理的 curl 明文流被过滤不入列表——若 composer 流也走过滤，调试自身请求可能被自己的忽略规则吞掉。Flow.Source=capture|composer 仅作标记，不过滤。
- **前端迭代闭环**：flows store 加 `composerShow/composerPrefillId` + `openComposer(id)`/`closeComposer()`；Composer.vue 发送成功后调 `store.select(newFlow)` 自动选中新流，用户可再点"调试重发"形成迭代链；响应区直接复用 BodyViewer（props `flowId` + `which="resp"`），解压/多视图零重写。非法 URL（非 http/https 绝对地址）后端返回 url.Error 且**不落库**，前端 message 报错。
- **入口禁用语义**：右键菜单与详情按钮在"无 URL 或 Method=CONNECT"时禁用（隧道流无明文请求可编辑）。
- **GUI 造流要用 PowerShell 不要用 curl**：curl.exe 在用户快捷忽略进程名单内，经代理造流不入列表（返回 200 但列表无流，易误判 bug）；`Invoke-WebRequest`（powershell.exe）未被忽略，是 M6/M5 类验收的标准造流法。
- **MCP 操作 n-modal**：Wails 的 n-modal 弹窗渲染在同一 webview 文档内，a11y 树里与主列表同树、元素 id 连续，直接 click 弹窗内元素 id 即可（无需切窗口）；弹窗打开后 id 全量重排，动作前重新取树。
- **通用组件清单（2026-09-05 提取）**：详情面板与 Composer 共用件已独立——`HeaderTable.vue`（headers map 拍平 key/value 双列只读表，替代 FlowDetail 的 h() 内联组件）、`CopyBar.vue`（props flowId+part，内聚 GetFlowRawText/copyText/message）、`BodyViewer.vue`（props flowId+which，七视图）。**新增展示旁路（M7 历史回放/M8 CLI 输出等）直接复用这三件，不要再内联重写。**
- **HTML 网页预览用 iframe srcdoc + 最小沙箱**：`sandbox="allow-same-origin"`（**绝不开 allow-scripts**——抓包工具渲染任意响应体，禁脚本/弹窗/表单提交是安全底线）+ `referrerpolicy="no-referrer"`；srcdoc 注入 `<base href="<ReqURL>">` 让相对 img/css/链接按原 URL 解析（BodyViewer 因此需并行拉 GetFlowDetail 取 ReqURL；非法 URL 容错）；无 head/html 的片段自动包 `<!doctype html><html><head><base></head><body>…`。自动视图识别：content-type 含 html/xhtml → web；无 CT 时正文 `<` 开头且前 1KB 有 `<html` → web。

## M8 关键认知（AI CLI 控制，2026-09-05）

- **同 exe 子命令拦截点**：`main.go` 在 `flag.Parse` 前拦截 `os.Args[1]=="cli"` → `ctlapi.RunCLI(configDir, os.Args[2:])`；`-headless` 与 `cli` 可组合（`PrismProxy.exe -headless` 起实例、`PrismProxy.exe cli ...` 控实例，同一 exe 两种角色）。
- **endpoint 发现文件落便携目录**：`config/ctl-endpoint.json`（{addr,token}，与 settings.json 同目录，**非旧规划 %APPDATA%\PrismProxy\cli-token**——便携模式是全项目既定约定，M4 后新配置一律走 `settings.DefaultConfigDir()`）；原子写 + 0600 + Windows icacls 限当前用户；实例 Close 时删文件；强杀残留 → cli 连接拒绝走友好错误提示（找不到/连不上 endpoint 文件），下次启动覆盖即可自愈。
- **`ctlService` 适配器规避 Wails binding 同名冲突**：ctlapi 包定义 `Service` 接口（只含控制面所需方法），main 包新增 `ctl_bridge.go` 用 `ctlService` 包装 `*App` 实现。**不要直接在 App 上加 ctlapi 方法**——App 已有同名 Wails binding（GetSettings/ListFlows/ClearFlows/GetFlowBody…），方法签名重复/冲突；适配器是唯一干净解，也让 ctlapi 包可独立单测（mock Service）。
- **Go flag 遇位置参数即停解析**：`PrismProxy.exe cli flows list --limit 5 --pretty` 这种"子命令后还跟全局 flag"的形态，原生 flag 包在 `flows` 处就停了，--pretty 收不到。自写 `reorderFlagsGlobal`（RunCLI 用，在完整 args 上只提取已知全局 flag --pretty/--addr/--token，**bool flag 不吞下一 token**）与 `reorderFlags`（子命令 flagSet 用，flag 全部前置到位置参数前）。**参数索引约定**：RunCLI 解析全局 flag 后 `pos := fs.Args()`，`pos[0]`=子系统名（status/flows/rules/…），各处理器内部 `args := pos[1:]` 再自行剥子命令与 flag；help 分支在 newClient 之前（help 不应要求实例在线）。
- **startup 时序竞态（GUI 顶栏恒显"代理已停止"）**：`startCtlAPI` 在 startup 开头同步执行（net.Listen + icacls ACL 子进程，数百 ms），把 StartProxy 推后；前端 onMounted 只调一次 `refreshStatus()` 且无轮询，首刷早于代理启动；而成功路径原本无事件（只有失败发 `proxy:start-error`）。修复=startup 末尾（自动启动+自动接管都完成后）发 `runtime.EventsEmit(ctx, "proxy:ready")`，前端 `EventsOn('proxy:ready', refreshStatus)`（立即拉 + 事件推双保险）。**以后在 startup 中加入任何同步耗时步骤都要考虑这条时序。**
- **UI 控制事件链路**：`cli ui clear` 是数据级动作（清 store），GUI 经既有 `flow:evict` 事件自动同步、headless 也执行（返回 {cleared,ui:false} 不报错）；`cli ui settings [tab]` 是纯界面动作，后端 `EventsEmit("ui:open-settings", tab)` → 前端 App.vue EventsOn → `showSettings=true` + `settingsTab=tab` + `WindowUnminimise()`（窗口最小化时恢复，否则用户看不到抽屉）；headless 无 UI 返回 `{"ui":false}`。tab 白名单 general/network/decrypt/capture/domains 服务端校验，非法 400。**SettingsPanel 已打开时外部切 tab**：watch 要监听 `[show, initialTab]` 而非只监听 show——面板开着时 tab 变更只切 activeTab 不 loadSettings（避免覆盖用户正在编辑的表单）。
- **headless 复用 App 服务层**：`runHeadless` 同样构造 `*App` + `startCtlAPI`（不 SetUI(true)、不起 Wails 运行时、不管系统代理），所以 ctlapi 全部命令在两种模式下行为一致；差异仅在 ui:* 命令的 `ui` 字段。
- **控制面安全口径**：仅绑 127.0.0.1:9595（独立于代理 9090，绝不绑 LAN）；Bearer token 用 `crypto/subtle.ConstantTimeCompare` 常量时间比较，支持 Authorization: Bearer 与 X-Prism-Token 两种头；token 32 字节 crypto/rand。
- **CLI 输出字段大小写口径（写文档/脚本时易踩）**：ctlapi 响应直接序列化 Wails binding 的结构体——`FlowMeta`/`FlowDetail`/`BodyPayload` **无 json tag，JSON 键为 PascalCase**（ID/State/Body/Raw…，字节字段是 base64 字符串）；而 `status`/`sysproxy` 是 ctlService 手构 map（小驼峰 running/flowCount/state），`settings` 走 settings.Settings（有 json tag，小驼峰 maxFlows/listenAddr…）。**面向用户的 CLI 使用说明见 [AI-CLI使用说明.md](./AI-CLI使用说明.md)（2026-09-05 新增，命令/字段/退出码/HTTP API 直连法均已核对实现）**。
- **cli e2e 实测法（headless + GUI 两场景）**：`PrismProxy.exe -headless` 后台起实例 → 同 exe `cli ...` 子命令打 9595 → `Invoke-WebRequest -Proxy http://127.0.0.1:9090 https://www.baidu.com` 造流（**用 powershell.exe 不用 curl.exe**，curl 在快捷忽略进程名单内）→ GUI 场景用 MCP Computer Use 截图验证抽屉/tab/列表同步；退出用 `taskkill`（发 WM_CLOSE→OnShutdown）验证 ctl-endpoint.json 干净消失。**PowerShell 多条原生 exe 命令在同一命令行执行时 stdout 会与 Write-Host 交错错位**——看到输出"串台"（如 settings get 打出 rules list 的内容）时单独重跑该命令确认，勿直接判 bug。

## M8.5 SSE 实时推送（2026-09-05 设计定稿 + 同日实施 + e2e 验收通过）

- 设计文档：[CLI实时推送设计.md](./CLI实时推送设计.md)；用户文档 [AI-CLI使用说明.md](./AI-CLI使用说明.md) §3.7。`GET /api/v1/events` SSE 双频道 flows/status + `ctlapi.Hub` fan-out（internal/ctlapi/hub.go）+ `cli flows watch`（cli_watch.go）。设计期 5 个关键决策（实施时全部落地，勿回退）：
  1. **快照-增量"先订阅后快照"**（连 /events → GET /flows → 输出 snapshot → 逐帧转发）：缝隙中创建且不再更新的流不会丢失；重叠区靠 upsert 幂等 + evict 忽略未知 ID。
  2. **flush() 早退陷阱**：`flush()` 在 `a.ctx == nil` 时早退，headless 下 ctx 恒 nil——hub fan-out 必须置于早退**之前**（有回归测试 TestHeadlessSSEFlowsFanOut 不设 a.ctx 守这条）。
  3. **ctlapi 不能 import app**（循环依赖）：过滤所需 host/url/path 经 `ctlapi.Filterable` 接口暴露，app.FlowMeta 实现 `FilterFields()`。
  4. **HTTP server 超时**：只设 `ReadHeaderTimeout`，**禁加 WriteTimeout/IdleTimeout**（杀 SSE）；Close 先 `Hub.Close()`（close 全部订阅 ch 让客户端立即 EOF）再 `Shutdown(2s)`（Shutdown 不断活跃长连接）。
  5. **watch 重连每次重读 endpoint**（实例重启 token 变）；事件流 client **无总超时**（Dial 10s/ResponseHeaderTimeout 30s）；退避 0.5s→1→2→4→8s、连续 5 次失败退出码 1；Ctrl+C/Break 退出码 0。
- **实施期固化的新陷阱（e2e/单测踩出，必读）**：
  6. **`[]Filterable` 接口切片 encoding/json 序列化成 `[{}]`**：接口类型字段无法导出，`FlowsUpsert.Flows []Filterable` 直接 json.Marshal 输出空对象数组——须给 FlowsUpsert 写自定义 `MarshalJSON` 逐条 marshal 具体类型再 strings.Builder 组装；测试侧反序列化也不能用含接口字段的类型，改用含具体 struct 切片的匿名结构。
  7. **事件流长连接必须与快照请求连接隔离**：watch 用独立 `streamHTTP` client（`DisableKeepAlives: true` + 请求 `req.Close = true`）打 /events，快照 GET /flows 走另一个 client——否则快照请求可能复用事件流的 keep-alive 连接，把 SSE 帧当 HTTP 响应消费，事件流静默无数据（最棘手的一个，排查了连接复用/scanner/过滤三层才定位，真因竟是 filter 不匹配，但隔离连接仍是必须的正确性保障）。
  8. **背压摘除只 close(reset) 不 close(ch)**：订阅者 128 帧缓冲突满时 Hub `delete(sub)` + `close(sub.reset)` 通知 handler 发 reset 帧返回；**不能 close(ch)**——handler 的 select 里 sink 关闭分支与 reset 分支会同时就绪，可能漏掉 reset 帧。
  9. **status 发布点与 StartProxy/StopProxy 拆分**：5 个发布点（startup 末尾 proxy:ready 后、StartProxy 成功/失败、StopProxy、SetSystemProxy on/off、settings 热重启、startCtlAPI 成功后）。为避免连调重复推帧，bindings_proxy.go 拆为公开 `StartProxy/StopProxy`（发 status）+ 内部 `startProxy/stopProxy`（不发，供 SetSystemProxy/SaveSettings 连调）。
  10. **query token 仅 /events 接受**：auth 中间件改 `auth(next, allowQuery ...bool)` 变参，query `token=` 只在 allowQuery 时生效（方便 curl/EventSource 直连，其余端点仍只认头）。未知频道 400、订阅上限 32 超出 503；订阅名额异步回收，测试需轮询 waitSubs 等计数回落。
  11. **【e2e 发现并修复的 M8 遗留路由 bug】Go ServeMux 精确模式不匹配子路径**：`mux.HandleFunc("/api/v1/flows", ...)` 只匹配该精确路径，`POST /api/v1/flows/clear` 会落到 `/api/v1/flows/` 子树 handler（handleFlowSub）返回 404"未知路径"——handleFlows 里的 clear 分支永远到不了，导致 `cli flows clear` 自 M8 起一直 404（无 HTTP 级 clear 测试所以没暴露）。修复=显式 `mux.HandleFunc("/api/v1/flows/clear", s.auth(s.handleFlows))` 注册（回归测试 TestFlowsClearEndpoint）。**教训：给 ServeMux 加"同前缀 + 动作子路径"路由时，精确 pattern 与子树 pattern 各管一段，动作子路径必须显式注册到目标 handler。**

## M7 关键认知（SQLite 持久化，2026-09-07）

- **模块形态（internal/persist）**：`Writer{db, queue chan *capture.Flow(2048), stop, wg, retainDays, maxMB, dropped/written atomic, active/paused atomic.Bool}`。**queue/stop channel 在 `Start()` 内创建**（Open 只建表不开队列——未 Start 时 Enqueue/Close 语义才确定，测试踩过）；`Enqueue` 仅终态（done/error）入队，先 `cloneFlow` 深拷贝（Header map + body 字节 append 复制 + PeerCerts 切片）再 `select { case queue<-f: default: dropped++ }` non-blocking 丢弃；`consumeLoop` 100 条/500ms 批量事务（两个 prepared stmt upsert），stop 时非阻塞排空队列再 flush 后退出。**绝不阻塞代理热路径**：Enqueue 是指针赋值 + 一次非阻塞 select。
- **两表 + body 分离**：`flows`（id PK + started_at 索引 + state/scheme/method/host/path/status/source + data=完整 Flow JSON，**序列化前 Message.BodyLen=len(Body) 再置 Body=nil**）；`bodies`（(flow_id,kind) PK，kind=req|resp，enc + raw_len + data blob）。body 压缩复用项目已有 `github.com/klauspost/compress/zstd` 包级 Encoder/Decoder（**EncodeAll/DecodeAll 并发安全**；zstd.NewWriter 返回 2 值，不是 std 风格；compress/zstd 不在 Go 标准库）；≥256B 且压缩后更短才存 zstd，否则原样。
- **历史流 body 惰性回查（内存有界关键）**：LoadRecent 时 body 不入内存，`Message.BodyLen` 记长度；前端详情/正文经 GetFlowBody/GetFlowRawText 时若 `len(Body)==0 && BodyLen>0 && Source==history` → `App.persistBody(id,kind)` → `Writer.LoadBody`（sql.ErrNoRows→(nil,nil)；enc=="zstd"→DecodeAll）回查并缓存到 msg.Body。历史流详情大小显示 `len(Body)>0 ? len(Body) : BodyLen`。
- **历史标记防回写**：`capture.SourceHistory="history"`；LoadRecent 反序列化后 `f.Source=history; f.Pinned=false`（置顶是会话内状态不持久化）经 `st.Add` 走正常 new 事件进 UI；`onPersistEvent` 订阅 store 事件时**跳过 Source==history** 避免把刚加载的历史又 Enqueue 回库。DTO `FlowMeta.Historical bool`（无 json tag，PascalCase 键），FlowList 主机列显示青色"历史"badge。
- **保留策略（审查后修正）**：retentionLoop 启动 2s 首跑 + 每 10 分钟。**必须开 `auto_vacuum=INCREMENTAL`**（DSN `_pragma=auto_vacuum(2)`，仅建表前生效；既有库在 migrate 里 `PRAGMA auto_vacuum=INCREMENTAL` 后 `VACUUM` 一次性迁移）——否则 SQLite DELETE 不缩小主 .db 文件（只产空闲页），`wal_checkpoint(TRUNCATE)` 只截断 WAL，`enforceSize` 的 `for dbSize()>max` 永不达标会一路删到表空（触阈值全清，maxMB 失效）。**WAL 模式收缩顺序铁律：DELETE → `PRAGMA incremental_vacuum`（空闲页释放写入 WAL）→ `PRAGMA wal_checkpoint(TRUNCATE)`（并入主库并截断 WAL，文件尾空闲页才归还 OS）；顺序反了主文件不缩、WAL 反增**。enforceSize 分批（chunk=64）删最旧 flows+bodies 并每批收缩，无数据可删即退出。dbSize=主文件 + -wal 合计（os.Stat）；retainDays/maxMB 为 0=不限。测试体积上限必须用 **crypto/rand 不可压缩体**，且断言要查**文件字节数回落**（仅断言条数减少会漏掉"不收缩"缺陷）。
- **【坑·锁重入死锁】pmu 临界区内严禁调用会同步触发 store 事件分发的方法**：`Store.emit` 在解锁后**同步**逐个回调订阅者（store.go emit），而 `onPersistEvent` 要取 `a.pmu`。若 `applyPersist/initPersist` 持着 pmu 调 `st.Add`（历史补载），emit→onPersistEvent→pmu.Lock 同一 goroutine 二次加锁不可重入 → 永久死锁（连带 UI 事件分发全卡死；可达场景：持久化运行中 + 历史流已被 Clear/环形淘汰后保存设置）。**约定：pmu 只保护 writer 指针读写；订阅与历史补载 `st.Add` 一律在 pmu 解锁后执行**（历史流 Source=history 被 onPersistEvent 跳过，无回写风险）。
- **retentionLoop 定时器必须可取消**：初版 `time.AfterFunc(2s,...)` 在 Close 后仍触发 → "database is closed"；改为循环内 `time.NewTimer(2s)` + ticker + stop 三向 select，stop 分支直接 return。
- **接线（internal/app/persist_wiring.go）**：用 **App 字段 `pmu sync.Mutex`** 保护 writer 指针（非包级变量——多测试实例不串状态）；NewApp 末尾 `initPersist()`；SaveSettings 在 rebuildEngine 后 `applyPersist(nu.Persist)`。**applyPersist 条件重连**：`Writer.Path()`（PRAGMA database_list 还原）取旧 DB 文件，路径不变仅 `Writer.UpdateRetention(retainDays,maxMB)` 热更新参数（不 Close/Open、不重扫）；路径变化或由关到开才 Close 旧→Open 新→LoadRecent 仅补 st.Get 不存在的 ID；关闭=Close writer 保留 DB 文件。Shutdown/headless 信号退出前 `stopPersist()`（先摘指针再 Close）。DB 路径：绝对直用、相对拼 cfgDir、空→`cfgDir/prism.db`。
- **历史正文回查失败不得静默**：`loadHistBody` 统一惰性回查——writer nil（持久化被关）→ isHist=false，绑定层经 BodyPayload.DecodeErr / 原文【持久化已关闭…】提示；DB 查询/解压出错 → log.Printf + 提示"回查失败"；正常无 body 行（LoadBody sql.ErrNoRows→nil,nil）静默。
- **marshalFlow 不要二次深拷贝**：Enqueue 已深拷贝隔离热路径（必要）；出队后对象仅单消费者 goroutine 只读，marshalFlow 只需浅拷贝 Flow + 浅拷贝 Request/Response 结构体置 Body=nil（BodyLen=len(Body) 先记），不要再 cloneFlow（body 字节复制纯浪费）。
- **GOPROXY**：modernc.org/sqlite 依赖树（libc/mathutil/memory/ncruces-go-strftime 等）拉取必须 `$env:GOPROXY='https://goproxy.cn,direct'`（默认 proxy.golang.org 被墙 dial 超时），后续所有 go 命令带此前缀。
- **【坑·headless 冒烟】settings.json 带 UTF-8 BOM → json.Unmarshal 失败静默回退 Default（持久化默认关，prism.db 不生成且无显式报错）**：Go 侧 settings.Save 写无 BOM 文件不会踩；**PowerShell 5.1 `Set-Content -Encoding UTF8` 写的是带 BOM UTF-8**（EF BB BF），手工造测试配置必须用 `[System.IO.File]::WriteAllText(p, json, (New-Object System.Text.UTF8Encoding($false)))`。排查抓手：进程不报错、配置不生效时先查文件头三字节。
- **测试设施**：persist 包 `paused atomic.Bool` + `setPaused()` 仅测试用——消费循环暂停时不排空队列，TestQueueDropWhenFull 靠 Start→setPaused(true)→灌满 queueCap+50→断言 Dropped()>=50。app 层 app_m7_test.go 用 newTestApp（cfgDir=t.TempDir）+ applyPersist 双 App 实例模拟重启。

## MITM 回写客户端的两条协议陷阱（2026-09-07 修复，internal/proxy/mitm.go）

客户端侧 TLS 握手 `NextProtos` 只给 `http/1.1`（老 Android okhttp/xutils/HttpURLConnection 只懂 h1），而上游 `http.Transport` 开 `ForceAttemptHTTP2` 常协商到 h2。回写响应曾直接 `resp.Write(bw)`，踩两个坑，均会让老旧 App 误判"未连接网络"：

1. **状态行协议号穿透**：h2 响应 `ProtoMajor=2`，`resp.Write` 给 h1 客户端写出非法状态行 `HTTP/2.0 200 OK`，老 okhttp 抛 `java.net.ProtocolException: Unexpected status line: HTTP/2.0 200 OK` → App 判无网络。抓包侧佐证：大量流 `reqProto=HTTP/1.1 respProto=HTTP/2.0`。
2. **流式响应不 flush（SSE/长连接致命）**：`resp.Write` 要把 body 读到 EOF 才返回，期间 bufio.Writer（4KB）从不刷新。SSE/IM 长连接 body 永不 EOF、事件帧仅几十字节，全积在缓冲——客户端连响应头都收不到，EventSource/IM SDK 判无网络。**且这种卡死的 goroutine 阻塞在 resp.Write 内、flow 不落库，flows 列表里"看不到 SSE 流"，极具迷惑性**。
- **修复**：弃用 `resp.Write`，新增 `writeH1Response` 手工组帧——状态行恒写 `HTTP/1.1`（上游真实协议仍记进 `flow.Response.Proto` 供 UI 展示，不影响展示）；上游无 Content-Length（h2 常态）转 h1 `Transfer-Encoding: chunked`；**状态行+首部写完立即 flush，body 32KB 逐块读取每块都 flush**（SSE 帧实时下发）；HEAD/204/304 无 body 剥分帧头。
- 对照：明文 HTTP 路径（handleHTTP）走标准 `http.ResponseWriter` 无此 bug；`writeSimpleResponse` 本就显式设 `ProtoMajor:1`（反证正常路径漏设）。

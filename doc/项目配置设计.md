# PrismProxy 项目配置设计（多项目隔离 + 热切换）

> 状态：设计定稿待实施（2026-09-07 定稿；2026-09-07 审计修订 v2：修正热切换步骤顺序、置顶/在途流/sysproxy 跨项目污染、互斥分层与 CLI 语义）。实施时同步更新 [开发进度.md](./开发进度.md) 与 [项目记忆.md](./项目记忆.md)。
> 关联文档：[方案.md](./方案.md) §4.8（Bindings/配置）、§4.11（SQLite 持久化）；[规则设计.md](./规则设计.md)（过滤/解密规则模型）。

## 一、背景与目标

当前所有配置只有**单份全局**文件 `config/settings.json`：过滤规则组、解密规则、系统代理绕过列表、域名组、监听地址、上游代理、ADB、持久化开关等全部混在一起。用户抓包不同目标 App 时，只能反复改规则、导入/删除域名组，历史流量也混在一个库里无法按目标区分。

**目标**：引入「项目（Project）」概念——每个抓包目标一个项目，规则类配置与流量历史按项目隔离；环境类配置（端口/上游/ADB 等机器属性）保持全局；顶栏下拉即可在**代理运行中热切换**项目，无需重启程序。

**本期范围（已拍板，见 §九）**：

1. **规则类按项目，环境类全局**：过滤规则组、解密规则、用户域名组随项目；监听地址/端口、上游代理、ADB、存储预算、UI 开关、**系统代理绕过列表（bypassList）**等全局共享。
2. **流量历史每项目独立 DB**：切换项目后列表只显示该项目抓到的流量。
3. **顶栏下拉 + 运行中热切换**：新建/重命名/复制/删除项目，切换时代理不重启、规则引擎热重建。
4. **目录形式**：`config/projects/<id>/` 每项目一个目录，携带各自 `project.json`、`domains/`、`prism.db`。

**不在范围**：项目导出/分享打包、项目级 CA、项目级监听端口、CLI 对非当前项目的 flows/sysproxy 等运行态操作（CLI 项目管理与规则读写见 §6.3）。

## 二、术语

| 术语 | 含义 |
|---|---|
| 全局配置 | 机器/环境属性，所有项目共享，存 `config/settings.json` |
| 项目（Project） | 一个抓包目标的完整隔离单元：规则 + 域名组 + 流量库（绕过列表 bypassList 属全局，不在项目内） |
| 当前项目 | 顶栏选中、规则引擎与流量列表正在使用的项目；指针存全局配置 |
| 项目视图（SettingsView） | GetSettings/SaveSettings 面向前端的合并 DTO（全局字段 + 当前项目规则字段），见 §6.1 |

## 三、目录结构与文件归属

### 3.1 新目录布局

```
config/
├── settings.json            # 全局配置（环境类 + 项目清单 + 当前项目指针）
├── ca/                      # 全局：Root CA 证书/私钥（设备只需信任一次，不按项目隔离）
│   ├── prism-ca.pem
│   └── prism-key.pem
├── ctl-endpoint.json        # 全局运行时：控制 API 发现文件（实例启停增删）
├── sysproxy-backup.json     # 全局运行时：系统代理接管前备份（崩溃自愈用）
└── projects/
    └── <projectId>/         # 每个项目一个目录
        ├── project.json     # 项目配置：规则组 + 解密规则（绕过列表在全局，见 §4.2）
        ├── domains/         # 该项目导入的用户域名组 <id>.txt
        └── prism.db         # 该项目的流量库（持久化开启时；-wal/-shm 随附）
```

### 3.2 配置项归属切分

现行 `settings.Settings`（[settings.go](../internal/settings/settings.go) §59-89）字段按「是否随抓包目标变化」切分：

| 字段 | 归属 | 理由 |
|---|---|---|
| `listenAddr` | **全局** | 机器监听属性，与抓哪个 App 无关 |
| `upstreamMode` / `upstreamProxy` | **全局** | 网络环境属性 |
| `maxFlows` / `maxBodyMB` | **全局** | 内存预算，机器属性 |
| `showSysProxySwitch` / `autoSysProxy` | **全局** | UI/行为偏好 |
| `bypassList` | **全局** | 系统代理绕过列表是**本机网络环境**属性（回环/本机服务/开发工具自身域名始终直连），与抓哪个 App 无关；接管系统代理时下发，全局唯一 |
| `adb` | **全局** | 模拟器/设备路径是机器环境 |
| `persist.enabled` / `retainDays` / `maxMB` | **全局** | 落盘总开关与保留策略；DB 文件本身按项目（见下） |
| `filterGroups` | **项目** | 过滤规则是项目的核心 |
| `decryptRules` | **项目** | 解密规则是项目的核心 |
| `persist.dbPath` | **废弃** | DB 路径固定为 `<项目目录>/prism.db`，不再允许自定义（见 §5.3） |
| `captureRules` / `processRules` | 迁移用旧字段 | 迁移逻辑在项目配置上同样执行一次（见 §8.1） |

**域名组**：从 `config/domains/` 迁到 `config/projects/<id>/domains/`，加载/写入目录由当前项目决定。
**CA、ctl-endpoint、sysproxy-backup**：路径与归属完全不变（仍是 `config/` 根）。

## 四、数据模型

### 4.1 全局配置 `config/settings.json`

```go
// GlobalSettings 全局（环境类）配置 + 项目清单与当前指针。
type GlobalSettings struct {
    ListenAddr    string `json:"listenAddr"`
    UpstreamMode  string `json:"upstreamMode"`
    UpstreamProxy string `json:"upstreamProxy"`
    MaxFlows      int    `json:"maxFlows"`
    MaxBodyMB     int    `json:"maxBodyMB"`

    ShowSysProxySwitch bool `json:"showSysProxySwitch"`
    AutoSysProxy       bool `json:"autoSysProxy"`

    // BypassList 系统代理 ProxyOverride 绕过列表（本机环境属性，全局唯一，见 §3.2）
    BypassList []string `json:"bypassList"`

    Persist PersistConfig `json:"persist"` // 仅 enabled/retainDays/maxMB 生效；dbPath 废弃
    ADB     ADBConfig     `json:"adb"`

    // 项目管理
    Projects      []ProjectMeta `json:"projects"`      // 项目清单（顺序即展示顺序）
    CurrentProject string       `json:"currentProject"` // 当前项目 id
}

// ProjectMeta 项目清单项（项目目录内 project.json 亦冗余 name，见 §4.2）
type ProjectMeta struct {
    ID   string `json:"id"`   // 项目 id（时间戳毫秒+序号，沿用规则组 ID 惯例）
    Name string `json:"name"` // 显示名（用户可改，必填、去空白、同清单内重名加序号区分）
}
```

`PersistConfig`（[settings.go](../internal/settings/settings.go) §92-97）保留结构体以兼容 JSON，但 `dbPath` 字段不再读取（加载时忽略、保存时不写）；DB 路径统一由 `projects/<id>/prism.db` 决定。

### 4.2 项目配置 `config/projects/<id>/project.json`

```go
// ProjectConfig 单个项目的规则类配置（项目目录内 project.json）。
type ProjectConfig struct {
    ID          string              `json:"id"`          // 与目录名一致，加载时校验
    Name        string              `json:"name"`        // 冗余自清单，便于单目录自识别/导出
    FilterGroups []rules.FilterGroup `json:"filterGroups"`
    DecryptRules []rules.DecryptRule `json:"decryptRules"`

    // 旧字段仅作迁移用途（与现行 Settings.Migrate 同一套逻辑）
    CaptureRules []rules.CaptureRule `json:"captureRules,omitempty"`
    ProcessRules []rules.ProcessRule `json:"processRules,omitempty"`
}
```

- 项目目录名 = 项目 ID；`project.json` 内 `id` 必须与目录名一致，不一致以目录名为准并告警（防手工改名导致漂移）。
- 新建项目的默认规则：`filterGroups`/`decryptRules` 为空（空白起点；如需沿用已有规则，新建时选择「从老项目复制」，见 §5.4）。内置绕过列表 `BuiltinBypass`（[settings.go](../internal/settings/settings.go) §122）属于**全局** `bypassList` 的默认值，不进项目配置。
- 写入沿用现行原子写（tmp + rename，文件 0600、目录 0700）。

### 4.3 内存模型（App 持有）

[app.go](../internal/app/app.go) §26-55 的 App 结构调整：

```go
type App struct {
    // ... 现有字段
    gcfg    *settings.GlobalSettings  // 取代 cfg *settings.Settings（全局部分）
    proj    *projects.Project         // 当前项目：cfg(ProjectConfig) + dir + groups(domains.Groups)
    // cfgDir 仍为 config 根目录；项目目录 = filepath.Join(cfgDir, "projects", proj.ID)

    projMu  sync.Mutex                // 项目切换/项目 CRUD/SaveSettings 串行化（互斥设计见 §5.4）
    projGen uint64                    // 项目代际，切换时递增；在途流终态按代际丢弃（见 §5.2）
}
```

- `eng *rules.Holder` 不变：热切换时用新项目的规则 + 该项目域名组重新 `rules.NewEngine` 后 `eng.Set`，代理与 recorder 通过 Holder 自动拿到新引擎（与现行 `rebuildEngine` 同一机制）。
- `groups *domains.Groups` 改为随项目：切换时从新项目目录 `domains.LoadUser`。

## 五、行为设计

### 5.1 启动与首次迁移

启动流程（`NewApp`，[app.go](../internal/app/app.go) §58）改为：

1. `cfgDir := settings.DefaultConfigDir()`（不变，仍便携模式 + 旧 %APPDATA% 搬迁）。
2. **检测升级**：`config/settings.json` 存在且**无** `projects` 字段 → 旧版单文件配置，执行一次性迁移（§8.1）；否则按新结构加载。
3. 加载全局配置；`projects` 为空时自动创建一个默认项目（名「默认项目」）。
4. `currentProject` 指向的项目目录缺失/损坏 → 回退到清单第一个项目并 log 告警。
5. 加载当前项目 `project.json`（缺失/损坏 → 默认项目配置兜底）、该项目 `domains/`。
6. 编译规则引擎、建 store、`initPersist`（DB 路径指向当前项目目录）。

### 5.2 热切换项目（代理运行中不重启）

切换 `SwitchProject(id)` 持 `projMu` 全程串行化（锁序见 §5.4），顺序执行：

1. 校验目标项目存在；与当前相同则 no-op。
2. **推进项目代际**：`projGen++`。此后旧代际在途流的终态一律丢弃（见下「在途流归属」）。
3. **清空内存流量列表**：`st.ClearAll()`（**含置顶**，见下「置顶语义」）——**必须先于新项目历史载入**，否则刚载入的非置顶历史流会被随后的清空误删（审计 v2 修正：原稿历史载入排在清空之前，顺序矛盾）。
4. **持久化换库**：`stopPersist`（同步刷盘关闭当前项目 writer）→ 记录新项目 id → 按全局 persist 配置打开新项目 DB → `LoadRecent` 载入该项目历史（`Source=history` 经 `st.Add` 走正常事件进入已清空的列表）。
5. **域名组**：`domains.LoadUser(<新目录>/domains)` 替换 `a.groups`。
6. **规则引擎**：用新项目 `filterGroups`/`decryptRules` + 新 groups 重新 `NewEngine` → `eng.Set`（编译失败沿用现行兜底：log warn + 空引擎全放行）。
7. 更新全局配置 `currentProject` 并落盘 `settings.json`。
8. 发 Wails 事件 `project:changed`（载荷 `{id, name}`）+ SSE status 帧；前端据此刷新设置面板、重置流列表 UI 状态。

> **系统代理绕过列表（bypassList）是全局配置**，不随项目切换变化，故切换流程不含 sysproxy 重下发；仅当 `SaveSettings` 修改了全局 bypassList 且系统代理接管中时，才走 `sysproxy.Reapply` 热下发（见 §5.5）。

**在途流归属（防跨项目污染）**：Flow 增加会话态字段 `gen`（不持久化），recorder 创建流时打标当前 `projGen`；流终态（done/error）写 store / Enqueue persist 前比对代际，不符则**直接丢弃**——不 `st.Add`（防止已清空的列表被旧项目流"复活"）、不入新项目库。权衡：切换瞬间的少数在途流在两个项目都不保留（persist 只落终态，旧库本就无此流）；替代方案（延迟关闭旧 writer 等在途流全部终结）复杂度高、收益小，拍板丢弃。

**置顶语义**：`store.Clear()` 保留置顶是 UI 顶栏「清空」按钮的语义（现行不变，有 TestClearKeepsPinned 守护）；**项目切换必须使用新增的 `st.ClearAll()`（连置顶一起清）**——置顶跨项目残留既违背隔离，其 body 惰性回查（`persistBody` 用当前 writer）还会查到新项目 DB 导致 body 静默丢失。ClearAll 后内存中无任何旧项目流，persistBody 只可能命中当前项目库。

**sysproxy 重下发（bypassList 保存即热下发）**：现行 `sysproxy.Enable` 是「合并当前注册表 Override」（`MergeOverride(cur.Override, bypass)`）且备份只在文件不存在时写。`SaveSettings` 修改全局 bypassList 后若直接重调 Enable，会把**已删除的旧 bypass 条目永久残留在注册表 Override**（合并不删旧值）。新增 `sysproxy.Reapply(bypass)`：读 `sysproxy-backup.json` 的原始 Override 为基线 → `MergeOverride(backup.Override, bypass)` → 写回注册表并广播刷新；**不重建备份**（备份仍是首次接管前的原值，供 Disable/崩溃自愈还原）、不广播"代理关闭"（避免窗口期断流）。备份缺失（异常态）时降级为合并当前值并 log 告警。注意项目切换不触发 Reapply（bypassList 全局，与项目无关）。

> 切换期间代理监听不中断、客户端连接不受影响；仅规则判定从下一请求起按新项目生效。切换动作短暂持有锁，规则引擎 Set 为指针替换，无长时间阻塞。

### 5.3 流量持久化按项目

- DB 路径解析 `dbPath()`（[persist_wiring.go](../internal/app/persist_wiring.go) §20）改为：`filepath.Join(a.cfgDir, "projects", a.proj.ID, settings.DefaultDBPath)`；不再读 `persist.dbPath`。
- 全局 `persist.enabled=false`（默认）时所有项目都不落盘；开启后每个项目在首次被使用（切换到/启动时）时打开自己的 `prism.db`。
- `retainDays`/`maxMB` 为全局策略，作用于每个项目库（打开各库时传入）。
- 网络设置页「DB 路径」输入框移除，文案改为「数据库按项目保存在 config/projects/<项目>/prism.db」。

### 5.4 项目管理操作

| 操作 | 语义 | 约束 |
|---|---|---|
| 新建 `CreateProject(name, fromID)` | 创建目录 + `project.json` + `domains/`，加入清单，**创建后自动切换**到新项目。`fromID` 为空=空白起点（规则为空、domains 为空）；`fromID` 非空=**从老项目复制**：拷贝其 `project.json`（filterGroups/decryptRules）与整个 `domains/`，但**不复制 prism.db**（历史流量不跟走），新项目 id/name 取新值 | 名称去空白非空；重名自动加「(2)」序号；`fromID` 必须存在 |
| 重命名 `RenameProject(id, name)` | 改清单与该项目 `project.json` 的 name（目录名/id 不变） | 当前项目可重命名；重名同上 |
| 删除 `DeleteProject(id)` | 删除项目目录（含 project.json/domains/prism.db）并从清单移除 | **不能删除当前项目**（前端先引导切换）；**至少保留一个项目**；删除前前端二次确认（明示流量库一并删除） |
| 切换 `SwitchProject(id)` | 见 §5.2 | — |

> 「复制项目」不再是独立后端方法，而是 `CreateProject(name, fromID)` 的一种入参（前端下拉里「新建项目」对话框提供「从已有项目复制规则」的可选来源下拉，默认空白）。复制仅携带**规则与域名组**，bypassList 是全局配置不在项目内、无需复制；历史 DB 永不复制。

- 所有项目清单变更后落盘全局 `settings.json`；项目规则变更落盘对应 `project.json`。
- 项目操作（切换/CRUD）与 `SaveSettings` 互斥：**新增独立锁 `projMu`，与保护代理运行态的 `a.mu` 分层**——不能直接用 `a.mu` 串行化：现行 `SaveSettings` 并不全程持 `a.mu`（Validate/Save 在锁外），且其尾部 needRestart 时要调内部需拿 `a.mu` 的 `stopProxy`/`startProxy`，全程持 `a.mu` 会自锁死。`SwitchProject`/项目 CRUD/`SaveSettings` 全程持 `projMu`；切换进行中保存快速失败（TryLock/原子标志，返回「正在切换项目」）。**锁序固定 `projMu` → `a.mu` / `a.pmu`，禁止反向**（SaveSettings 尾部重启代理时已是 `projMu` → `a.mu` 顺序，无死锁）。

### 5.5 配置保存语义（SaveSettings 拆分）

前端设置面板仍一次性提交整个表单。后端 `SaveSettings` 把入参拆两半：

- 环境字段（listen/upstream/maxFlows/maxBodyMB/开关/**bypassList**/persist/adb）→ 校验并写入全局 `settings.json`；监听/上游变化且代理运行中仍自动重启代理（现行逻辑不变）。**bypassList 变化且系统代理接管中时调 `sysproxy.Reapply` 热下发**（基线重建语义，见 §5.2「sysproxy 重下发」）——注意这是本期新增行为：现行版本 `SaveSettings` 不重新下发 bypass（仅监听/上游变化才重启代理），实施时勿遗漏此路径。
- 规则字段（filterGroups/decryptRules）→ 补全规则组 ID、Validate 规则可编译性后写入**当前项目** `project.json`，热重建引擎。
- 全局 persist 开关变化 → `applyPersist`（对当前项目库生效）。

## 六、后端接口（Wails Bindings / ctl API）

### 6.1 面向前端的合并 DTO

为最小化前端改动，`GetSettings()` 返回**合并视图**而非两套结构：

```go
// SettingsView 全局环境字段 + 当前项目规则字段（前端表单原样绑定）。
type SettingsView struct {
    // 环境（全局）
    ListenAddr    string `json:"listenAddr"`
    UpstreamMode  string `json:"upstreamMode"`
    UpstreamProxy string `json:"upstreamProxy"`
    MaxFlows      int    `json:"maxFlows"`
    MaxBodyMB     int    `json:"maxBodyMB"`
    ShowSysProxySwitch bool `json:"showSysProxySwitch"`
    AutoSysProxy       bool `json:"autoSysProxy"`
    BypassList   []string            `json:"bypassList"` // 系统代理绕过列表（全局，见 §3.2）
    Persist PersistConfig `json:"persist"`
    ADB     ADBConfig     `json:"adb"`
    // 规则（当前项目）
    FilterGroups []rules.FilterGroup   `json:"filterGroups"`
    DecryptRules []rules.DecryptRule   `json:"decryptRules"`
    // 项目上下文
    CurrentProject ProjectMeta `json:"currentProject"`
}
```

`SaveSettings(view *SettingsView)` 入参同形，后端按 §5.5 拆分落盘。`SaveSettingsResult`（warnings）不变。

**`CurrentProject` 是只读输出字段**：`SaveSettings` 一律**忽略**入参中的 `currentProject`（及任何 `projects` 字段），切换项目的唯一入口是 `SwitchProject` binding。必须如此——CLI `settings set` 是整结构 `json.Unmarshal` 后走同一 `SaveSettings`，若不忽略该字段，CLI 就能绕过切换校验直写当前项目指针（等价无校验的 SwitchProject 后门）。

> 说明：前端各 Tab 表单字段名与现状完全一致，仅网络 Tab 去掉 dbPath 输入；规则相关 Tab 无需感知「项目」概念，保存即写入当前项目。

### 6.2 新增项目管理 Bindings

```go
ListProjects() ([]ProjectMeta, error)              // 项目清单（含当前项标记由 currentProject 决定）
GetCurrentProject() (ProjectMeta, error)           // 当前项目
CreateProject(name, fromID string) (ProjectMeta, error) // 创建并切换；fromID 非空=从该项目复制规则+域名组（不复制 DB）
RenameProject(id, name string) error
DeleteProject(id string) error
SwitchProject(id string) error                     // 热切换
```

Wails 事件：`project:changed`（载荷 `{id, name}`），前端顶栏/设置面板/流列表监听。

### 6.3 CLI / ctl API

CLI（[ctlapi](../internal/ctlapi)）经 ctl bridge 复用与 GUI 同一套保存路径。项目化后规则类命令**默认作用于当前项目**，并新增全局 `--project <id|名称>`（简写 `-P`）指定目标项目：

**项目选择规则**：
- 不带 `--project`：作用于全局配置里的 `currentProject`（GUI 顶栏当前选中项）。
- 带 `--project <id|名称>`：精确匹配项目 id；未命中则按项目**名称**匹配（区分大小写、重名时提示用 id）；仍未命中报错并列出可用项目。
- **对非当前项目的写操作只改该项目的 `project.json`/`domains/` 文件，不改变 GUI 的 currentProject、不触发引擎热切换**（GUI 正在抓包，规则引擎只认当前项目）；若写的正是当前项目则照常热重建。

**命令语义**：

| 命令 | 项目化后语义 |
|---|---|
| `project list` | 列出全部项目（id/名称/是否当前） |
| `project switch <id\|名称>` | 切换当前项目（等价 GUI 热切换，走 `SwitchProject`） |
| `project create <名称> [--from <id\|名称>]` | 新建项目（`--from` 从老项目复制规则+域名组，不复制 DB），创建后成为当前项目 |
| `project rename <id\|名称> <新名称>` / `project delete <id\|名称>` | 重命名 / 删除（不可删当前项目、至少保留一个） |
| `rules list` | 读目标项目 filterGroups/decryptRules（受 `--project` 影响） |
| `rules ignore host\|process` | 快捷忽略双内置组写入目标项目 `project.json` |
| `rules group enable/disable`、`rules decrypt mitm\|bypass` | 写目标项目 `project.json`（现为直写 settings.json，必须改） |
| `rules import / export` | 作用目标项目：导入写 `project.json` + 该项目 `domains/`；导出读该项目 |
| `settings get` | 输出 §6.1 SettingsView 合并视图（含 `currentProject` 只读上下文）；`--project` 时规则字段取指定项目 |
| `settings set` | 与 GUI `SaveSettings` 同路径：环境字段写全局、规则字段写目标项目；**`currentProject`/`projects` 字段被忽略**（见 §6.1），CLI 不能经 `settings set` 切换项目（切换走 `project switch`） |
| `flows …` / `sysproxy …` / `status` / `ui …` | 不受 `--project` 影响（flows/sysproxy 是运行态：内存列表与库、系统代理均属当前运行实例） |

- `--project` 为全局 flag（置于子命令前后均可，由 CLI 参数解析统一提取，不下发给 bridge 业务方法）。
- `ctl-endpoint.json` 发现机制不变；CLI 仍通过本地控制 API 连接正在运行的实例执行，项目 CRUD 复用 §6.2 bindings。

## 八、迁移与兼容

### 8.1 旧版单配置 → 多项目（一次性，幂等）

启动时检测到旧 `settings.json`（无 `projects` 字段）：

1. 备份旧文件为 `settings.json.bak-v1`（不破坏现状，可回退）。
2. 创建默认项目：id 取 `<时间戳>-1`，目录 `config/projects/<id>/`。
3. **移动**（失败回退拷贝）旧资产进项目目录：
   - `config/domains/` → `projects/<id>/domains/`（用户域名组）。
   - 若 `config/prism.db` 存在（持久化曾开启）→ `projects/<id>/prism.db`（含 -wal/-shm）。
   - 若旧 settings 的 `persist.dbPath` 指向**自定义路径**（非默认 `config/prism.db`）：该 DB **不自动迁移**（任意路径无法安全归属），仅 log 告警「原数据库保留在 <路径>，不再被读取」；用户可手动将其移入项目目录改名 `prism.db`。
4. 生成 `project.json`：取旧 settings 的 `filterGroups`/`decryptRules`，并在其上执行一次 `Migrate()`（旧 captureRules/processRules 迁移、`_quick_ignore` 拆组，与现行逻辑同源）。
5. 生成新全局 `settings.json`：环境字段照抄（**含 `bypassList`，绕过列表归全局**），`projects=[{id,name:"默认项目"}]`，`currentProject=id`；不写 `dbPath`。
6. 迁移幂等：已存在 `projects` 字段则跳过；任一步骤失败 log 告警并以「全局默认 + 空默认项目」启动，不阻塞程序。

> 旧 `%APPDATA%\PrismProxy` 搬迁逻辑（[settings.go](../internal/settings/settings.go) §31）保留：先于项目迁移执行，把旧 settings.json 搬到 config 根，随后项目迁移接管。

### 8.2 全新安装

无 `settings.json` → 写全局默认 + 创建「默认项目」目录与默认 `project.json`。

## 九、拍板记录

1. **隔离范围 = 规则类按项目、环境类全局**（2026-09-07；同日修订）：filterGroups/decryptRules/域名组归项目；端口/上游/ADB/预算/开关/**bypassList** 归全局。**bypassList 是本机网络环境属性（回环/本机服务/开发工具自身域名始终直连），不随抓包目标变化，定全局唯一**（初稿曾归项目，用户拍板改全局）。CA 全局（设备信任一次）。
2. **流量历史每项目独立 DB**（同日）：`projects/<id>/prism.db`；废弃 `persist.dbPath` 自定义路径。
3. **热切换**（同日）：代理不重启，规则引擎指针热替换；切换清空内存流（含置顶，审计 v2 修订）并载入新项目历史。**切换不涉及 sysproxy 重下发**（bypassList 全局，与项目无关）。
4. **目录形式 `config/projects/<id>/`**（同日）：而非平铺单文件——项目需携带独立 domains/ 与 prism.db，目录形式扩展干净。
5. **新建项目支持「从老项目复制」**（同日拍板）：`CreateProject(name, fromID)`，`fromID` 非空时拷贝源项目规则 + 域名组，**不复制 prism.db**（历史不跟走）；创建/复制后自动切换；删除仅允许非当前项目且至少保留一个。
6. **GetSettings/SaveSettings 保持合并视图**（SettingsView）：前端表单字段名不变，改动面最小；项目概念仅在顶栏切换器与后端落盘路径体现。
7. **切换清空内存流含置顶**（2026-09-07 审计修订）：新增 `st.ClearAll()` 供切换使用；UI「清空」按钮仍用 `Clear()` 保留置顶（现行语义不变）。置顶跨项目残留会导致 body 惰性回查错库（见 §5.2）。
8. **在途流按项目代际丢弃**（同日）：切换瞬间 streaming 流的终态不入新列表/新库（recorder 打标 `projGen`，终态比对丢弃），防跨项目污染。
9. **sysproxy 重下发走基线重建**（同日）：新增 `sysproxy.Reapply`——以备份原 Override 为基线合并 bypassList 写回；直接重调 `Enable`（合并当前注册表值）会把已删除的旧 bypass 条目永久残留在注册表。**触发点仅为 `SaveSettings` 修改全局 bypassList 且系统代理接管中**（项目切换不触发）。
10. **项目互斥用独立锁 `projMu`**（同日）：与 `a.mu` 分层、锁序 `projMu → a.mu/a.pmu`（直接用 `a.mu` 会与 SaveSettings 尾部重启代理死锁）；`SaveSettings` 忽略入参 `currentProject`/`projects`，切换唯一入口 `SwitchProject`。
11. **CLI 支持指定/管理项目**（同日拍板）：规则类命令默认作用当前项目，新增全局 `--project/-P <id|名称>` 作用于指定项目（对非当前项目的写只改其文件、不触发热切换）；新增 `project list/switch/create/rename/delete` 子命令。flows/sysproxy 等运行态命令不受 `--project` 影响。

## 十、测试计划

**Go 单测**：
- 全局/项目配置 Load/Save：缺字段默认兜底、损坏文件降级、原子写。
- 迁移：旧单文件 settings + domains/ + prism.db → 默认项目目录内容正确、全局 projects 指针正确、幂等（二次调用 no-op）、备份文件存在。
- `SwitchProject`：规则引擎切换后命中新项目规则；store **ClearAll 后无置顶残留** + 新项目历史载入完整（验证先清后载顺序）；旧代际在途流终态被丢弃（不入列表、不入新库）；切换**不触发** sysproxy 调用（bypassList 全局，mock 断言无 Reapply 调用）。
- `SaveSettings`：入参携带 `currentProject`/`projects` 被忽略（当前项目指针不变）；切换进行中保存返回「正在切换项目」；修改 bypassList 且接管中触发一次 `Reapply`、注册表 Override = 备份原值 + 新列表、已删除条目不残留（mock sysproxy）。
- 项目 CRUD：重名加序号、不能删当前/最后一个；`CreateProject(name, fromID)` 复制后规则与域名组与源一致、**prism.db 不复制**（新目录无 db 或为空库）。
- CLI：`--project` 按 id/名称解析（重名报错提示 id、不存在列清单）；写非当前项目只改其 project.json 且 currentProject 不变、不触发热切换；`project switch/create/delete` 约束与 GUI 一致。
- 持久化：两个项目各自 prism.db 独立、切换后写入落到正确库。

**验收（手工/造流）**：
1. 新建项目 A、B，分别配不同过滤规则与域名组，导入不同域名组；热切换时代理不重启、列表随项目切换、规则即时生效（造流命中/过滤符合各项目规则）。
2. 开持久化，A 项目抓流 → 切 B 看不到 A 的流 → 切回 A 历史还在。
3. 系统代理接管中：切换项目 ProxyOverride 不变（bypassList 全局）；在设置里修改绕过列表保存后，ProxyOverride 按新列表重建、已删除条目不残留。
4. 旧版 config 升级：规则/域名组/历史 DB 完整迁入默认项目，bypassList 保留在全局 settings，程序正常启动。
5. 删除项目目录被清除且不可删当前项；重命名、新建（空白/从老项目复制，副本无历史 DB）行为符合 §5.4。
6. CLI：`prismproxy rules list --project <名称>` 读到指定项目规则；`project switch` 后 GUI 顶栏同步切换。

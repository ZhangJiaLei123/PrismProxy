# PrismProxy 过滤规则设计（黑白名单模式 + 多规则组）

> 状态：设计定稿待实施（2026-09-04 定稿；同日完成可行性审计修订：信息缺失维度移除规则、path 段边界、隧道无 path、@引用警告校验、迁移与接线补齐——见 §九 拍板记录）。实施时同步更新 [开发进度.md](./开发进度.md) 与 [项目记忆.md](./项目记忆.md)。
> 关联文档：[方案.md](./方案.md) §4.7（原三层规则）、§4.9（复制/快捷忽略）。

## 一、背景与目标

M4 落地的规则体系为三层平铺有序列表（捕获/解密/进程，首条命中 + 默认动作），存在以下不足：

1. **无黑白名单模式概念**：默认"全记录 + exclude 屏蔽"事实上等价黑名单模式，但白名单（只显示指定目标）需要用户手工编排 include 条目 + 末尾兜底 exclude，且**进程层做不到**（进程未知视为未命中走默认 include，无"空 name 兜底"机制），无模式开关、无引导。
2. **无用户自建规则组**：`@组名` 仅能引用 go:embed 内置 domains/ 厂商组（只读），用户不能创建自己的"一组域名/路径/进程"集合并整组启用/停用。
3. **无独立路径维度**：捕获规则只有 `urlRe`（对完整 URL 做正则），普通用户写正则门槛高。

**目标**：筛选规则分为**黑名单模式 / 白名单模式**（默认黑名单），支持**多个规则组**，一组内含多个域名 / 路径 / 进程配置，可命名、可整组启用/停用。域名为"不显示 / 只允许显示"两类语义。

**范围**：仅改造"捕获/显示过滤"层。解密规则（MITM/bypass）维持平铺不变；前端展示层搜索过滤（关键字/方法/状态码）不变。

## 二、核心语义

### 2.1 规则组模型

```
FilterGroup {
  id        string    // 后端保存时生成（时间戳毫秒+序号，沿用 M1 零外部依赖惯例）
  name      string    // 用户可读组名，必填
  enabled   bool      // 整组开关，false 整组跳过
  mode      string    // "blacklist"（默认）| "whitelist"
  hosts     []string  // 域名条目（裸域名 / @内置组名）
  paths     []string  // 路径 glob 条目
  processes []string  // 进程名条目（精确匹配，不区分大小写）
}
```

- **组内维度之间是 AND，同维度多条目之间是 OR**：`hosts=[a.com,b.com]` 表示任一命中即 hosts 维度命中；三种维度都配置了才要求全部命中；只配置部分维度则只检查配置的维度。
- **组与组之间是 OR**（见 2.2 组合语义）。
- **空组不匹配任何流量**（黑名单空组无副作用；白名单空组等价不存在——见 2.2 判定"启用中的白名单组"以"组内有条目"为准）。

### 2.2 模式定义与多组组合（deny-override）

| 模式 | 组内条目命中的含义 |
|---|---|
| blacklist（默认） | 命中 → **不显示**（正常转发但不入列表） |
| whitelist | 命中 → **只显示这些** |

多组组合判定顺序（防火墙经典 deny-override）：

```
ShouldDisplay(host, rawURL, procName):
  1. 任一【启用中的黑名单组】命中 → false（黑名单最高优先，拒绝覆盖允许）
  2. 否则若存在【启用中的白名单组】（非空）：
       任一白名单组命中 → true
       全部不命中      → false
  3. 无启用中的白名单组 → true（默认全显示，即纯黑名单场景）
```

**"启用中的白名单组（非空）"谓词**（引擎判定 / UI 状态条 / 空组提示三处必须一致实现，防前后端漂移）：

```
isActiveWhitelist(g) = g.Enabled && g.Mode == "whitelist" && (len(g.Hosts)+len(g.Paths)+len(g.Processes) > 0)
```

注意：谓词按**静态字面条目**判非空，与运行时"维度移除"（§2.3）无关。

效果对照：

- 默认（无组 / 只有黑名单组）= **黑名单模式**：全显示，命中黑名单的屏蔽。与现状行为兼容。
- 建一个白名单组"只抓某 App 相关域名" = **白名单模式**。
- 白名单组 + 黑名单组并存 = 白名单收窄后黑名单再排噪（如"只抓网易 + 屏蔽其心跳路径"）。

### 2.3 信息缺失维度的统一边界（进程未知 / 隧道无 path）

两类流存在维度信息缺失：

- **进程未知**（procName 为空）：模拟器（雷电/MuMu）流量统一归因到 `VBoxNetNAT.exe`，多实例无法按进程精确区分（项目记忆既有结论）。
- **盲透传隧道无 path**：bypass/pinning 降级的 CONNECT 隧道 flow，URL 仅有 `https://host` 无 path（tunnel.go 现状）；**path 维度仅对已解密（MITM）与明文 HTTP 流量生效**。

统一规则（**维度移除**，三条形式化，替代原"该维度视为未配置"的模糊表述）：

1. 流缺失某维度信息（procName 为空 / path 为空）→ 该维度**从该组的约束集中移除**（仅对该流生效）。
2. 组对该流命中 ⇔ 剩余约束全部命中；**剩余约束为空（组本来无条目，或条目全在被移除维度）→ 该组对该流不匹配**。
3. §2.2 判定中"启用中的白名单组"以**静态非空**为准（规则同上节谓词），与运行时维度移除无关。

> 为什么不采用"缺失维度=恒真命中"：那样纯进程黑名单组（`processes=[dnplayer.exe]`）遇未知进程流会命中 → **全部未知进程流量被隐藏**，与现状"未知进程不命中规则走默认 include"相悖（回归性误伤）；纯进程白名单组则会放行全部未知进程流，"只看某进程"失效。

推论（向后兼容现状 + 已知局限）：

- 纯进程黑名单组遇未知进程流 → 组不命中 → **不误伤**（同现状语义）。
- 纯进程白名单组遇未知进程流 → 组不命中 → 流被隐藏（保守，符合白名单直觉）。因此白名单组里若配了进程，UI 给出提示：**模拟器场景建议按域名/路径建白名单**。
- hosts+paths 混合白名单组遇隧道流 → 只剩 hosts 约束，hosts 命中即显示（符合直觉）。
- 纯 path 白名单组遇隧道流 → 组不匹配（path 拿不到，不可避免——文档明示此局限）。
- 黑名单 path 条目拦不住隧道流（维度移除后组不命中）——属预期；隧道行降噪靠 host 维度或解密层 bypass。

## 三、匹配规则

| 维度 | 语义 |
|---|---|
| hosts | 裸域名 = 自身 + 全部子域（`baidu.com` 覆盖 `api.baidu.com`，同现有 `bareMatch`）；`*.x.com` 通配写法等价裸域名；`@组名` 引用内置 domains/ 域名组；统一小写比较 |
| paths | **glob 匹配**：`*` 跨任意字符（含 `/`）、`?` 单字符；**无通配符条目按"精确或子路径"匹配**（`/telemetry` 命中 `/telemetry`、`/telemetry/x`，**不命中 `/telemetryx`**——段边界）；`/` 单独一条 = 匹配所有路径；只匹配 URL 的 path 部分，不含 query；大小写敏感（路径惯例） |
| processes | 进程名精确匹配、不区分大小写（同现状） |

path 编译策略（审计修订：双形态，无通配符不走正则）：

- **含 `*`/`?` 的条目**：编译为正则（`*` → `.*`、`?` → `.`、其余 `regexp.QuoteMeta`，锚定 `^...$`），缓存在引擎编译产物中（每组一次编译，热路径只做匹配）。
- **无通配符条目**：不编译正则，热路径直接字符串比较 `path == entry || strings.HasPrefix(path, entry+"/")`——免正则开销，且天然带段边界（`HasPrefix` 裸前缀会让 `/telemetry` 误中 `/telemetryx`、`/api/v1` 误中 `/api/v10`）。
- **path 提取**：`url.Parse` 失败或提取为空（隧道流 URL 无 path）→ **降级为空 path**，走 §2.3 维度移除（不拿原始 URL 串去匹配——锚定 `^/` 的语义对完整 URL 永不匹配，等于隐性失效）。

示例：

| 条目 | 命中 | 不命中 |
|---|---|---|
| `/api/v1/*` | `/api/v1/user/info` | `/api/v2/x` |
| `/telemetry` | `/telemetry`、`/telemetry/upload` | `/telemetryx`、`/api/telemetry2`（段边界） |
| `*/heartbeat` | `/v1/heartbeat` | `/heartbeatx` |
| `/` | 任意 path | —（单独使用等价"全路径"，须与 hosts/processes 组合才有意义） |

## 四、数据模型与持久化

### 4.1 settings.json 结构

```go
// internal/rules/engine.go（模型放 rules 包，settings 引用，同现有惯例）
type FilterGroup struct {
    ID        string   `json:"id"`
    Name      string   `json:"name"`
    Enabled   bool     `json:"enabled"`
    Mode      string   `json:"mode"`      // blacklist | whitelist
    Hosts     []string `json:"hosts"`
    Paths     []string `json:"paths"`
    Processes []string `json:"processes"`
}

// internal/settings/settings.go
type Settings struct {
    // 现有字段全部不动：ListenAddr / UpstreamMode / UpstreamProxy /
    // MaxFlows / MaxBodyMB / BypassList / DecryptRules
    FilterGroups []rules.FilterGroup `json:"filterGroups"`

    // 旧字段仅作迁移用途：Load 迁移后清空并重写落盘
    CaptureRules []rules.CaptureRule `json:"captureRules,omitempty"`
    ProcessRules []rules.ProcessRule `json:"processRules,omitempty"`
}
```

- `Default()` 须初始化 `FilterGroups: []rules.FilterGroup{}`（否则新配置序列化出 `"filterGroups": null`，前端需额外判空）。

### 4.2 校验（Validate）

签名改为 `Validate() (error, []string)`：第一返回值为阻塞错误（拒绝保存），第二返回值为**非阻塞警告**（保存照常成功，SaveSettings 透传前端展示）。

- `mode` 只能是 `blacklist | whitelist`；非法值报错。
- `name` 非空。
- `paths` 全部 glob 可编译（编译失败报组名 + 条目）。
- `hosts` 条目非空、**不允许裸 `*`**（语义过宽必是手误，报错）。
- `hosts` 中 `@组名` 引用**校验存在性但只产生 warning 不阻塞**（审计修订，原"不校验"太激进）：未知引用记入 warnings（含组名 + 条目），保存照常成功，前端对未知 `@tag` 标红。理由：白名单组只含失效 `@引用` → 整组永不命中 → 白名单模式下全部流量消失且无提示，用户无法自救。数据源复用 `ListDomainGroups`（内置组清单）。
- `ID` 为空由后端 SaveSettings 时补全，前端不生成；**同一次 Save 新增多组时 ID 须加循环序号去重**（时间戳毫秒+序号，避免同毫秒碰撞）。

## 五、引擎设计

### 5.1 编译结构

```go
type Engine struct {
    groups  []filterCompiled  // 过滤规则组（编译后）
    decrypt []DecryptRule     // 解密层不动
}

type filterCompiled struct {
    FilterGroup
    hosts []string      // hosts 展开产物：@组名 在编译期预展开为具体裸域名清单（引用缺失展开为空），热路径不再查 groups map
    paths []pathMatcher // paths 编译产物（双形态）
}

// pathMatcher 双形态（§三 编译策略）：无通配符条目免正则
type pathMatcher struct {
    exact string         // 无通配符条目非空：用 ==/HasPrefix 字符串比较（段边界）
    re    *regexp.Regexp // 含通配符条目非空
}
```

（原设计 `groups0 map[string][]string` 运行时查表改为编译期展开——现状 hostMatch 每次查 map + 线性扫，展开后热路径只做 bareMatch 比较。）

### 5.2 判定入口

删除 `ShouldCapture` / `ShouldCaptureProcess` 两个方法，统一为：

```go
// ShouldDisplay 返回该流是否显示（黑名单/白名单 + deny-override 语义见 §2.2）
func (e *Engine) ShouldDisplay(host, rawURL, procName string) bool
```

- 内部从 `rawURL` 提取 path；`url.Parse` 失败或 path 为空（隧道流）→ 按 §2.3 维度移除处理（**不降级拿原始串匹配**，理由见 §三）。
- `procName == ""` / `path == ""` 时该维度对该流移除（§2.3 统一规则）。
- 方法保留 **nil receiver 安全**（`if e == nil { return true }`）：Holder 热替换间隙与启动编译失败兜底均依赖此行为（现状同款约定）。
- 解密判定 `ShouldDecrypt(host)` **完全不动**。

### 5.3 接线改动

| 位置 | 改动 |
|---|---|
| [internal/proxy/server.go](../internal/proxy/server.go) `ApplyRulesFilter` | `rec.Filter` 回调改为单次调用 `eng.ShouldDisplay(hostOnly(f.ServerAddr), rawURL, procName)`，删除原进程/URL 两次判定 |
| [app.go](../../app.go) / [main.go](../../main.go) 启动处（审计补齐） | 两处相同链路：`Load → Migrate() → 返回 true 则 Save 落盘`，随后 `NewEngine(cfg.FilterGroups, cfg.DecryptRules, gmap)` |
| [app.go](../../app.go) `rebuildEngine` | `NewEngine(a.cfg.FilterGroups, a.cfg.DecryptRules, gmap)` |
| [internal/settings/settings.go](../internal/settings/settings.go) `Validate` | 内部 `NewEngine(s.FilterGroups, s.DecryptRules, nil)` 换新签名（校验可编译性） |

`NewEngine` 新签名：`func NewEngine(filterGroups []FilterGroup, decRules []DecryptRule, groups map[string][]string) (*Engine, error)`

**启动编译失败兜底**（审计补齐，现状两处启动均静默吞错）：编译失败 → log warn + **空引擎全放行**（GUI 可选在设置页顶部告警"规则编译失败，当前过滤未生效"）；保存设置链路（rebuildEngine）失败则**拒绝保存并回显错误**（与现状 Validate 拦截一致）。

**热更新在途流**（审计明确，沿用现状不处理）：Begin 时旧引擎放行、Finish 时新引擎过滤 → 该行停留 streaming 不再更新（现状已有，非新引入）；发生概率低，环形淘汰兜底。不为过滤判定引入 Flow 级首次判定记忆。

`CaptureRule` / `ProcessRule` 类型保留（仅供迁移代码引用），引擎不再使用。

## 六、旧配置自动迁移

迁移发生在 `settings.Load` 之后（`Settings.Migrate()`），返回是否发生迁移以提示保存：

| 旧数据 | 迁移目标 |
|---|---|
| `captureRules` 中 `action=exclude` 条目 | 黑名单组（host → hosts；urlRe/method 维度**丢弃**并在日志提示） |
| `captureRules` 中 `action=include` 条目 | 白名单组（同上） |
| `processRules` 中 `action=exclude` 条目 | 黑名单组 processes |
| `processRules` 中 `action=include` 条目 | 白名单组 processes |
| `decryptRules` | 不迁移、不改动 |

- 迁移组命名（审计修订，按 action 区分黑白避免重名）：`旧捕获规则-黑名单(迁移)` / `旧捕获规则-白名单(迁移)` / `旧进程规则-黑名单(迁移)` / `旧进程规则-白名单(迁移)`，`id` 前缀 `_migrated_`（黑白各加分段后缀保证唯一），`enabled=true`。同一来源（捕获/进程）的 include 与 exclude 并存时会产生两个不同名组。
- 多条同 action 旧条目合并进同一个迁移组的对应数组（保持黑名单/白名单语义聚合）。
- **迁移幂等**：迁移完成后清空旧字段落盘一次，二次启动旧字段已空 → 不再生成迁移组。当前实际存量配置基本为空，迁移代码保留保证向前兼容。
- urlRe/method 丢弃的依据：path glob 替代正则、HTTP 方法过滤由前端展示层搜索承担（见 §九 拍板记录）。
- **已知语义漂移**（可接受，文档明示）：① 旧有序列表"首条命中" vs 新 deny-override——如旧 `[include baidu, exclude baidu+urlRe:/ads]` 旧行为=全收 baidu（include 在前先命中），新行为=baidu 先被黑名单组整域屏蔽；② 旧条目 host+urlRe 组合屏蔽在 urlRe 丢弃后退化为**整域屏蔽**（更严）。迁移日志须提示含 urlRe 条目的语义变化。存量为空，不做逐条等价转换。

- **添加条目交互**（2026-09-05 二次调整）：保留"先选维度（域名/路径/进程）再填值"的单入口，值控件按维度切换——域名维度是"引用域名组下拉 + 手输域名"二合一的 tag-select（域名组引用只在此维度出现，选"进程"时无此入口）、路径维度输入框+添加按钮、进程维度进程序 tag-select；条目平铺展示后维度前缀即类型标识，模型仍是 hosts/paths/processes 三个数组不变。进程维度下拉选项为系统全部运行进程（新 binding `ListSystemProcesses`，internal/procs 包 Toolhelp32 快照枚举，小写去重排序、排除 PID 0/4）合并已捕获流量 ProcessName（前端 flows store 兜底，覆盖枚举时刻未运行/权限不足的进程）。

## 八、M5 联动调整（2026-09-04 实施完成）

- **快捷忽略——双内置黑名单组**（原单组 `_quick_ignore` 设计已修订）：右键"忽略此域名"写入 `_quick_ignore_hosts`（名称"快捷忽略-域名"，hosts 维度），"忽略此进程"写入 `_quick_ignore_procs`（名称"快捷忽略-进程"，processes 维度），两组均 `enabled=true, mode=blacklist`，组间 OR 各管一维。**拆双组的原因**：组内维度 AND——域名+进程若混在同一组，"忽略此域名"加的 host 会与"忽略此进程"加的 proc 互相收窄（host 命中但 proc 不命中 → 整条不屏蔽），两个快捷动作会彼此失效；拆成两个单维组后各自独立命中。Binding `AddQuickIgnore(target, value)` 语义不变（target=host/process，幂等去重，组不存在自动创建，热更新 + 落盘 settings.json）；存量旧混合组 `_quick_ignore` 由 `settings.Migrate` 启动时自动拆分为双组（按条目维度归位，幂等可重入）。双组在设置-过滤规则页与普通组卡片同构展示（折叠卡片、可开关、可删条目、可整组删除）。
- **规则导入导出**（已实施）：导出 `ExportRules(embedGroups)` 走原生保存对话框，JSON 含 `version=1 / exportedAt / filterGroups / decryptRules / bypassList`，`embedGroups` 勾选时内嵌 `groups`（用户域名组 id→域名清单，无用户组时 omitempty 省略）。导入 `ImportRules(src)`：`src=""` 走原生打开对话框、`http(s)://` 前缀走 URL 拉取（20s 超时、4MB 上限、默认 http.Client 不读系统代理）、否则按本地路径读；`version` 必须为 1；nil 切片兜底为空；内嵌 `groups` 自动 `domains.WriteUser` 补建用户域名组；**整体替换** filterGroups/decryptRules（bypassList 非 nil 才替换）；替换后 `Validate` 编译性错误阻塞、未知 `@引用` 作为 warnings 非阻塞返回并弹窗逐条列出；校验通过即落盘 + 热更新（监听地址/上游变化时重启代理）。前端导入前弹"整体替换"确认框（不可点遮罩关闭），导入后 `emit('imported')` 刷新设置表单。

## 九、拍板记录

| 议题 | 决定 | 理由 |
|---|---|---|
| urlRe 正则与 method 维度 | **直接移除**（path glob + 展示层方法过滤替代） | 保持组模型简单；正则使用门槛高；方法过滤在列表搜索已可用 |
| 规则组排序/拖拽 | **不做** | deny-override 语义下组间无顺序依赖（黑名单 OR、白名单 OR、黑名单恒优先），仅启用开关即可 |
| 进程未知 / 隧道无 path 的维度处理 | **维度移除 + 剩余约束空则组不匹配**（2026-09-04 审计） | "视为未配置=恒真"会使纯进程黑名单组误伤全部未知进程流（与现状"未知进程不命中"相悖）、纯进程白名单组放行全部；形式化三条规则见 §2.3 |
| 无通配符 path 匹配 | **精确或子路径（段边界），字符串比较不走正则**（2026-09-04 审计） | 裸 `HasPrefix` 会让 `/telemetry` 误中 `/telemetryx`、`/api/v1` 误中 `/api/v10`；字符串比较免正则开销 |
| `@组名` 引用存在性 | **校验 + warning 不阻塞**（2026-09-04 审计，原"不校验"修订） | 白名单组只含失效 @引用 → 永不命中 → 全部流量消失且无提示，用户无法自救 |
| `url.Parse` 失败降级 | **降级为空 path 走维度移除**（2026-09-04 审计，原"取原始串"修订） | 锚定 `^/` 的匹配语义对完整 URL 串永不匹配，原方案等于隐性失效 |
| 热更新在途流 | **沿用现状不处理**（2026-09-04 审计） | Begin 放行 + Finish 过滤 → 行停留 streaming，概率低、环形淘汰兜底，不值得引入 Flow 级判定记忆 |

## 十、测试计划

### 10.1 单元测试（internal/rules/engine_test.go 重写）

- 无组 → 全显示（黑名单默认语义）。
- 单黑名单组：域名（裸域/子域/`@组名`）、路径 glob 边界（前缀、`*`、`?`）、进程；组内 AND（host+path 同时配置需同时命中）、同维度多条目 OR、组间 OR。
- 单白名单组：只显示命中；未命中不显示；空组等价不存在。
- 黑白并存：白名单收窄 + 黑名单 deny-override 排除。
- enabled=false 整组跳过。
- glob 编译失败报错（Validate / NewEngine 均覆盖）。
- **维度移除（§2.3 审计核心）**：纯进程组 × procName 空 × 黑/白两模式（黑名单不误伤未知进程、白名单隐藏未知进程）；纯 path 组 × 隧道流（rawURL 无 path，不匹配）；hosts+paths 混合组 × 隧道流（只剩 hosts 约束，hosts 命中即命中）；hosts+processes 混合组 × procName 空（只剩 hosts）。
- **path 段边界**：`/telemetry` 不命中 `/telemetryx`；`/api/v1` 不命中 `/api/v10`；`/` 命中任意 path。
- `url.Parse` 失败的 rawURL → 空 path 走维度移除（非原始串匹配）。
- nil Engine 的 `ShouldDisplay` 返回 true。

### 10.2 单元测试（internal/settings/settings_test.go）

- 旧 captureRules/processRules → filterGroups 迁移（exclude→黑名单、include→白名单、urlRe/method 丢弃、decryptRules 不动、迁移后旧字段清空）。
- **迁移幂等**：迁移落盘后二次 Load/Migrate 不重复生成迁移组。
- **include+exclude 并存**：迁移组命名黑白区分、id 唯一。
- Validate：非法 mode、坏 glob、空 name、裸 `*` host 报错；未知 `@引用` → warning 不阻塞（Validate 可成功返回 warnings）。

### 10.3 GUI 验收

1. 建白名单组只含某域名 → 列表仅该域名流量。
2. 在其上加黑名单路径组 → 对应路径流量消失，其余白名单命中仍显示。
3. 停用组 → 恢复全量显示。
4. 旧配置（含 captureRules/processRules 的 settings.json）启动 → 自动迁移，设置页可见迁移组（黑白分组命名），功能等价；重启二次启动不重复生成迁移组。
5. 黑名单默认新建组 → 屏蔽指定域名生效（正常转发但列表不出现）。
6. 白名单组填入不存在的 `@引用` → 保存成功但出现 warning 提示、设置页该 tag 标红。
7. 纯进程黑名单组（如 dnplayer.exe）+ 产生未知进程流量（如 curl）→ 未知进程流量**不被隐藏**（维度移除回归验证）。

## P1 proxypool 包（新包 internal/proxypool）

### 任务
- [x] P1-1 `entry.go`：`ProxyEntry{Host,Port,Username,Password,ExpireAt,Region,Source,Raw}` + `Endpoint{Addr,Username,Password}`（Resolver 出参，不含 Raw）
- [x] P1-2 `provider.go`：`Provider` 接口（Vendor/Fetch/AccountInfo/AddWhitelist/DelWhitelist/ListWhitelist）+ `FetchResult/AccountInfo/WhitelistInfo/VendorMeta` 类型（+ 可选能力接口 `MyIPer`）
- [x] P1-3 `registry.go`：`map[VendorID]func() Provider` + `Register/Lookup/Vendors()`，常量 `Vendor91HTTP = "91http"`
- [x] P1-4 `provider_91http.go` 适配器：
  - 厂商 client 三铁律：独立 `http.Client{Transport:&http.Transport{Proxy:nil}}`、连 5s/总 10s、日志脱敏（URL 抹 query，只记 code/msg/数量）
  - Fetch：固定 `format=json&time=1&pw=1&protocol=1`，条件 isp/province/city/filter；成功判定 `code==0||code==200`；JSON 防御解析（`data.list`/`data.proxy_list`/`data.ips`/顶层 data 数组；元素对象多键名或字符串扩展行）→ text 回退（sep 切行，`ip:port[,expire,user,pwd]` 保守解析）
  - AccountInfo（order/get-info：auth_username/auth_password/surplus）、白名单三接口、get-my-ip（本机公网 IP）
  - 基址常量 `http://api.91http.com`（可注入，测试用 httptest）
- [x] P1-5 解析夹具单测：text/json 两套样例（含已知形态变体）、失败 code+msg 透传、HTTP 非 200
- [x] P1-6 `manager.go` Manager：
  - 生命周期：`NewManager(conf)` / `Start()` 异步首提 / `Stop()`（停续期 goroutine）
  - `atomic.Pointer[ProxyEntry]` 粘滞当前出口 + 池切片；自建 `mu+inflight` 单飞（不引 x/sync）
  - `Resolver() func(ctx) (*Endpoint, error)`：有货原子读（纳秒级）；窗口期等单飞上限 ResolveWaitSec（随 ctx 取消）；超时/冷却期落 OnEmpty（direct→nil,nil + Degraded=true；error→错误带「冷却剩余 N 秒」）
  - 续期：到期前 RefreshAheadSec 后台提新，成功原子切换；补池：池 < MinPoolSize 触发；退避：连续失败 2/5/10s 封顶 60s
  - 坏点：`ReportBad(addr)` 连续达 MaxRetry 剔除换下一个，池空补池；防环命中由引擎层上报
  - `Rotate()` 手动换 IP；`Status() PoolStatus`（DTO 无 Raw/secret/password，含 Fetching/Degraded）
  - 事件回调 `SetOnStatusChange(func(PoolStatus))`（App 挂 Wails 事件推送）
- [x] P1-7 Manager httptest 单测：首提/到期续期/坏点剔除/退避冷却/Resolving 窗口等待与超时/OnEmpty 两态/Degraded 翻转/单飞并发/Status 不含敏感字段（13 用例）

### 出口 AC
- `go test ./internal/proxypool` 全绿；包不依赖 internal/proxy（类型单向：App 层薄适配）

## P2 代理引擎改造（internal/proxy）

### 任务
- [x] P2-1 `server.go`：`Options` 增加 `UpstreamResolver func(ctx) (*UpstreamEndpoint, error)`；定义 `UpstreamEndpoint{Addr,Username,Password}`；resolver 非 nil 优先于静态 UpstreamProxy
- [x] P2-2 `Transport.Proxy` 改闭包：取 endpoint（含 ctx），nil 直连，err 返回；`url.URL{Scheme:"http",Host:ep.Addr}` + userinfo 预置账密（S2：Go 只在 userinfo 时预置 Proxy-Authorization）。静态/动态统一走闭包，行为等价
- [x] P2-3 DialContext 包装坏点埋点：dial 失败且 addr==当前 upstream（`curUpstream` 原子指针）才上报 `OnBadEntry`；目标站超时/直连失败不计（实测断言）
- [x] P2-4 roundTrip 出口 407 识别：resp.StatusCode==407 → 记坏点 + `RotateUpstream` 回调 + 捕获体重放换新 entry 重试一次；仍 407 或 body 截断则透传客户端
- [x] P2-5 逐次动态防环：resolver 返回的 Addr 每次过 `GuardUpstreamLoop`，命中上报坏点并取下一个（防死循环上限 `maxUpstreamResolveAttempts=16`，> MaxRetry×常规池容量；引擎不知池大小的等效实现）
- [x] P2-6 `tunnel.go`：`dialViaUpstream(ep *UpstreamEndpoint, target, timeout)` 签名改造，CONNECT 加 `Proxy-Authorization: Basic`（原始 user:pass base64，与 net/http 同口径）；407 返回 `errUpstreamAuth`（errors.Is 可判）并上报坏点+触发换 IP；handleConnect 盲透传分支先 resolver(ctx)，nil 直连、err 回 502
- [x] P2-7 单测（upstream_test.go 10 用例全绿）：静态模式回归不变、resolver 闭包动态切换、userinfo 预置、407 重试一次、407 两次透传、防环命中剔除、dial 坏点归因（直连不误杀）、resolver err 502、隧道鉴权头+407、静态隧道级联真转发

### 出口 AC
- `go test ./internal/proxy` 全绿；manual/system 旧路径行为不变

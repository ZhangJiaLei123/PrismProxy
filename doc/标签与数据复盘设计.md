## 一、需求

1. **给抓包数据加标签**：允许为一批抓包流打一个命名标签（归档语义），标签随数据持久化。
2. **标记按钮**：顶栏「清空」按钮旁新增「标记」按钮，给**当前列表中的数据**（当前过滤后可见的流）打标签，并落库。
3. **标记弹窗**：点击标记按钮弹出对话框：
   - 填写标签名称；
   - 复选框「标记后自动清空当前列表」——**勾选状态本次运行缓存，重启后默认不勾选**；
   - 标签名称输入框**本次运行缓存**（上次输入内容回填），并带**清空图标**（一键清空输入）。
4. **数据复盘页面**：新增独立「数据复盘」页面，**支持新窗口打开**；入口放在**顶部标题栏**。
5. **复盘数据范围分离（v3 新增）**：数据复盘页将「**手动归档**（打了标签）的数据」与「**自动保存**（自动录制落库）的数据」分开展示；**默认只显示归档数据**，提供切换控件可查看**全部数据**（含自动录制落库但未打标的流）。
6. **未开启自动保存也可手动归档（v3 明确为正式需求）**：顶栏「归档」按钮（[AppHeader.vue](../frontend/src/components/AppHeader.vue) 标记按钮，原 L38–45）**不依赖自动录制开关**——自动保存关闭时，仍可对当前列表手动打标签归档，数据同样进入复盘页。（现状核查：已满足——archive Writer 与录制开关完全解耦、按需懒打开，见 §4.2；本需求将其固化为验收项 AC19。）
7. **时间窗口筛选 + 密度时间轴（v3 新增）**：数据复盘页新增**时间窗口筛选**与**可拖拽时间轴**：时间轴按数据密度以**色彩温度**着色（低密度暗色 → 高密度暖亮色）；支持在时间轴上**拖拽框选**时间窗、**平移/缩放**选区、点击空白清除；列表按窗口过滤。

## 三、总体方案

```
┌─────────────────────────────── 主窗口（Wails webview，单窗口）───────────────────────────────┐
│  AppHeader: [项目切换] [数据复盘↗] …… 流计数 [暂停][标记🏷][清空][GitHub]                      │
│                                        标记弹窗(n-modal)：标签名(可清空) + ☐标记后自动清空列表  │
│  FlowList(新增标签列) + FlowDetail(概览展示标签)                                              │
└───────────────┬───────────────────────────────────────────────────────────────────────────┘
                │ Wails Bindings（打标签 / 取复盘地址）
                ▼
        ┌─────────────────── App（Go）───────────────────┐
        │  persist.Archive（标签归档库，按需懒打开）        │
        │    tags 表 + flow_tags 表 + flows/bodies 复用    │
        │  ctlapi Server（127.0.0.1:9595, token）          │
        │    dist 静态托管(/review.html + /assets/)        │
        │    + /api/v1/tags...                             │
        └───────────────┬───────────────────────────────┘
                        │ BrowserOpenURL(http://127.0.0.1:9595/review.html?token=xxx)
                        ▼
        ┌──────────── 系统浏览器（独立新窗口，复盘页 review.html）────────────┐
        │  标签侧栏 + 流列表 + 详情/正文 + 标签管理(重命名/删除)                │
        │  [范围: 归档|全部](v3) + 密度时间轴(色温着色/拖拽选窗)(v3)           │
        │  数据走 fetch(/api/v1/tags/...)，Header: Authorization: Bearer <tok> │
        └───────────────────────────────────────────────────────────────────┘
```

**核心决策**：

- **标签 = 归档**。打标签即把这批流（元数据 + 请求/响应正文）完整、持久地写入项目库，且不受「自动录制」开关与保留策略（retention）影响。标签是比置顶（会话内、易失）更长期的「收藏/归档」。
- **新窗口 = 系统浏览器 + ctlapi 托管**。这是 Wails v2 唯一能给出「真正独立 OS 窗口」的路径，且复用既有本地 HTTP/token/SSE 基建，无需引入多窗口黑科技。
- **闭环（v2 新增）**：复盘页的打标/重命名/删除与主窗共用同一批 App 方法，方法内部统一完成「DB 写 → tagIndex 刷新 → pendUp 推送」，主窗徽章不产生双源漂移（§4.4）。
- **范围分离（v3 新增）**：复盘页数据范围默认「归档」（打标流，v2 现状语义），可切换「全部」（库内全量 flows，含自动录制落库未打标流）。后端以 `scope` 查询参数实现，无 schema 变更（§4.4）。
- **时间轴 = 密度直方图 + brush 选窗（v3 新增）**：时间轴不是装饰性进度条，而是**可交互的密度直方图**：底图为全域分桶直方图（色温着色），用户在其上拖拽框选时间窗 → 列表按 `start/end` 过滤；查询走既有 `idx_flows_started` 索引（§4.4、§6.4）。

## 四、后端设计

### 4.1 数据库 schema（persist 包，`migrate()` 内幂等新增）

在现有 `flows`、`bodies` 两表基础上新增两表：

```sql
-- 标签字典
CREATE TABLE IF NOT EXISTS tags (
    id          TEXT PRIMARY KEY,          -- 标签 id = "t_" + sha256(归一化名) 前 12 位 hex（见下），同项目内唯一
    name        TEXT NOT NULL,             -- 展示名（用户原始输入，trim 后）
    created_at  INTEGER NOT NULL,          -- unix 毫秒
    last_used_at INTEGER NOT NULL          -- unix 毫秒，最近一次打标时间
);

-- 流 ↔ 标签 多对多关联
CREATE TABLE IF NOT EXISTS flow_tags (
    flow_id    TEXT NOT NULL,
    tag_id     TEXT NOT NULL,
    tagged_at  INTEGER NOT NULL,          -- unix 毫秒
    PRIMARY KEY (flow_id, tag_id)
);
CREATE INDEX IF NOT EXISTS idx_flow_tags_tag ON flow_tags(tag_id);
CREATE INDEX IF NOT EXISTS idx_flow_tags_flow ON flow_tags(flow_id);
```

- **标签 id 采用 hash（v2 修订，替代 v1 的「小写归一化名直接作 id」）**：
  - `normalizeTagName(name)`：trim、空白折叠为单空格 → **展示归一化名**（「登录流程」「登录流程 」「Login/login」合并语义与 v1 一致）；
  - **id = `"t_" + hex(sha256(去全部空白 + lower 的归一化名))[:12]`**。hash id 一劳永逸消除 v1 的四类隐患：① id 含中文/内部空格作 URL 路径段的编码问题；② 与字面路由段 `flows` 的歧义；③ 与特殊值 `all` 的冲突；④ 路径分隔符/通配符注入面（`ValidTagID` 退化为 `^t_[0-9a-f]{12}([0-9a-f]{4})?$`）。
  - name 保留首次/最近展示形态；标签名长度限制 1–40 字符（对 name），空串、纯空白拒绝。
  - 碰撞处理：48bit 碰撞概率可忽略，仍设防线——插入时发现同 id 不同归一化名，后插入者改用前 16 位 hex 重查（实现一处循环即可）。
- `flows.data` 里的 `capture.Flow` JSON **不**内嵌标签（标签是库层面的关联，避免双源漂移）；流的标签集合通过 `flow_tags` 查询得到。

### 4.2 DB 打开策略：标签归档库独立懒打开（与自动录制解耦）

**问题**：M7 语义是「持久化默认不开启」，`prism.db` 仅在自动录制开时才创建/打开。但标签必须在用户**没开自动录制**时也能落库；且打标签时内存流可能已被环形淘汰/或正文已不在内存。

**方案**：在 `persist` 包复用现有 `Writer` 类型（它已封装 flows/bodies 写入、zstd、migrate、WAL），新增一个**标签归档专用实例**，由 App 持有、**按需懒打开、随项目切换关闭**：

- App 新增字段 `archive *persist.Writer`（与 `persist *persistOwner` 分开），配 `archiveMu sync.Mutex`（语义独立单独锁，避免与录制事件链路死锁）。
- `ensureArchive() (*persist.Writer, error)`：
  - 无打开项目（M11 无项目态）→ 返回「请先打开或创建项目」错误；
  - `archive != nil` 直接返回；
  - 否则 `persist.Open(dbPath, retainDays=0, maxMB=0)` → `Start()`。**关键（v2 已核实源码）**：`retainDays=0, maxMB=0` 表示**关闭保留清理**——按龄 DELETE 以 `retainDays > 0` 门控、enforceSize 以 `maxMB > 0` 门控，0 即跳过，不是取默认值；migrate 仍会建好全部表（含 tags/flow_tags）。
  - **残余行为说明（v2）**：retentionLoop 仍每 10 分钟执行孤儿 body 清理 + `wal_checkpoint(TRUNCATE)`（无条件段）。对归档数据无害（反而有利于回收 DeleteTag 残留空间）；与录制 Writer 并发时 checkpoint 偶发 busy 失败会被忽略、刷日志，可接受，不为此加开关。
  - 项目切换（`switchPersist` 链路 / `enterNoProjectLocked` / `CloseProject`）时一并关闭旧 archive（`Close()` 置 nil），新项目首次打标再懒打开。
- **自动录制与归档共存（v2 修订：BUSY 对策）**：若自动录制也开着，会出现两个 `Writer` 指向同一 `prism.db`——即**两个独立连接池、两条写连接**。`SetMaxOpenConns(1)` 只保证池内串行，**跨池不串行**；modernc.org/sqlite 官方 FAQ 明确并发写必然可能遇到 `SQLITE_BUSY`。v1「busy_timeout(5s) 重试覆盖」的假设过于乐观：录制单批事务最多 100 条 × 每条 body 上限 2MB + zstd 压缩，慢盘上可超 5s。对策：
  1. archive 侧 DSN 单独 `busy_timeout(15000)`；
  2. `ArchiveFlow` 内置 **BUSY 退避重试**（如 3 次 × 1s，重试耗尽才向上报错）；
  3. 批量打标写库**按每 50–100 条一个事务分批提交**，压缩单次持锁窗口（TagFlows 长事务同样会阻塞录制批量写）；
  4. flows/bodies 写均为 `INSERT OR REPLACE` 幂等 upsert，互不破坏；tags/flow_tags 仅 archive 写。
  5. **实施必做验证（AC11）**：录制灌流中同时批量打标 ≥2000 条含大 body 的流，断言零 BUSY 未重试错误。
  - 备选（更稳但改动大）：打标签时若录制 Writer 已开则复用同一 Writer 写 flows/bodies，仅 tags/flow_tags 走 archive——**不采用**（两套写路径合并复杂、且录制关闭场景仍需 archive），统一走 archive，靠上述 1–4 兜底。

### 4.3 打标签流程（后端核心）

新增 Wails 绑定（`internal/app/bindings_tags.go`，新文件）：

```go
// TagFlows 给一批流打标签并归档。ids 为流 ID 列表（前端传当前过滤可见流，后端去重）；
// name 为标签名；autoClear=true 时打标完成后由后端原子清空列表（保置顶，v2 修订）。
// 返回 {tag, tagged, archived, skipped} 统计。
func (a *App) TagFlows(ids []string, name string, autoClear bool) (*TagResult, error)

// ListTags 当前项目的标签列表（含计数、最近使用时间），供弹窗历史标签下拉与复盘侧栏。
func (a *App) ListTags() ([]TagInfo, error)

// GetReviewURL 返回复盘页地址（ctlapi 基址 + token），供前端 BrowserOpenURL。
func (a *App) GetReviewURL() (string, error)
```

`TagFlows` 步骤（整体在旁路 goroutine 执行，不进 pmu 临界区同步触发 store 事件——沿用 [persist_wiring.go](../internal/app/persist_wiring.go) 文件头死锁规避规则）：

1. 校验项目已打开、name 合法（1–40 字符）、ids 非空；**ids 去重**（HTTP 入口可传重复）。
2. `w := a.ensureArchive()`。
3. 归一化 name → hash tagID；`INSERT OR IGNORE INTO tags` 新建，再 `UPDATE tags SET last_used_at=?`（已存在则刷新）。
4. 对每个 id（**每 50–100 条一个事务分批提交**，单条写走 `ArchiveFlow` 内置 BUSY 重试）：
   - 从 `a.st.Get(id)` 取内存流：
     - **命中内存流**：深拷贝（复用 `persist` 的 `cloneFlow`/`marshalFlow` 逻辑，剥 body 入 bodies、长度记 BodyLen）→ `w.ArchiveFlow(f)`（upsert flows+bodies，幂等）。
     - **未命中内存**（已被环形淘汰）：查归档库/录制库是否已有该 id 的 flows 行——有则跳过 flows 写入（正文若 bodies 缺失则尽力从录制库补；补不到也接受，因为该流本就没落过盘）；无则计 `skipped`（数据已不可得，前端提示 N 条因已过期未归档）。
   - `INSERT OR IGNORE INTO flow_tags(flow_id,tag_id,tagged_at)`。
5. **刷新 tagIndex（copy-on-write，v2 明确并发方案）**：
   - `tagIndex map[flowID][]tagName` 的读方有三类并发上下文：store 事件回调（`toMeta`）、Wails 绑定线程（ListFlows/GetFlowDetail）、ctlapi HTTP goroutine——裸 map 并发读写 = 进程级 fatal。
   - **方案：copy-on-write + `atomic.Pointer`**——tagIndex 用不可变 map 快照，写侧（TagFlows/LoadRecent 回填/项目切换清空/RenameTag/DeleteTag）整体重建新 map 后原子替换指针；读侧（`tagsOf`）零锁取快照。
   - **铁律（与 persist_wiring 死锁规则同级别写死）**：**tagIndex 写侧重建期间不得触发任何 store 事件发射**（否则 TagFlows 持写状态同步 emit → onStoreEvent → toMeta 读 tagIndex → 重入）。若实施时改用 RWMutex 而非 COW，此铁律同样适用。
   - 锁序声明：`projMu → archiveMu / tagIndex 写重建`；tagIndex 不与 `a.mu` 交叉持有。
6. **回显推送（v2 修订：不走 store，走 pendUp）**：Store 没有「对既有流主动发 update 事件」的公开 API（已核实），v1「经 store 发出 update 事件」无实现路径。改为：对**内存中仍存在**的被打标流构造 `FlowMeta`（`toMeta` 注入最新 Tags），**批量投入 App 既有的 flow:upsert 合帧缓冲（pendUp）**。**不得直接 `EventsEmit`**——若勾选 autoClear，`st.Clear()` 的 evict 事件经 `onStoreEvent` 会删除 pendUp 中同 id 的待发 upsert，走 pendUp 时序天然正确（清空后列表不复活）；直接 emit 则竞态。
7. **autoClear（v2 修订：后端原子执行）**：`autoClear=true` 时打标完成后调用 `a.st.Clear()`（保置顶，与前端 `clear()` 语义一致）。由后端一步完成，消除「前端打标 await → 再 await clear」两步之间的中间态竞态（paused/关弹窗等）。
8. 返回统计：`tag`(TagInfo)、`tagged`(新增关联数，去重后口径)、`archived`(本次写 flows 的流数)、`skipped`(已过期无法归档数)。

**归档写方法**（persist 包新增）：

```go
// ArchiveFlow 归档单条流（元数据 + 正文），upsert 幂等。与录制 Enqueue 不同：
// 同步写（调用方在旁路 goroutine/用户动作，非代理热路径），不受队列/开关影响。
// 内置 SQLITE_BUSY 退避重试（见 §4.2）。
func (w *Writer) ArchiveFlow(f *capture.Flow) error
```

内部复用 `writeBatch` 的单条 upsert（抽出现有 SQL 为 `upsertFlow(tx, f)`），或直接小事务写 flows+bodies。

**标签回显的取数口径**（v2 定稿，吸收原引注）：

- 内存流的标签不能只靠会话态字段（历史补载流、重启后的流也要显示标签）。统一口径：
  - App 维护内存标签索引 `tagIndex`（flowID → 标签名列表），在 `TagFlows`/`RenameTag`/`DeleteTag` 后以 COW 方式更新；在 `LoadRecent`/补载历史流后（启动、录制由关到开、项目切换三处），对补载的 id 批量 `SELECT flow_id,tag_id JOIN tags` 一次性回填；
  - `toMeta` 从 COW 快照读 `Tags`（`tagsOf(f.ID)`）；未命中索引视为无标签（不查库，保证列表热路径零 DB）；
  - 项目切换时随 ClearAll 清空 tagIndex（COW 置空快照）；
  - **`capture.Flow` 不加 Tags 字段**（避免污染领域模型与 flows.data）；标签索引放在 App 层，`toMeta(f)` 转换时注入。

**v3 参数语义（scope / start / end / buckets）**：

- **`scope`（范围分离，需求 5）**：
  - `archived`（默认、缺省值）＝ 打标流（现状谓词 `id IN (SELECT flow_id FROM flow_tags)`，即 v2 已实施的「全部已标记」语义）；
  - `all` ＝ 库内全部 flows（含自动录制落库但未打标的流），谓词放开；
  - **`scope` 仅在 `tagID=all` 时生效**；选中具体标签时该参数被忽略（按 archived 处理——标签下必然是打标流，宽容处理不报 400，拍板 §九 11）；**非法 scope 值（非 `archived`/`all`/空）返回 400**（与既有 writeErr 400 语义一致）；
  - **`total` 口径随 scope**：`archived` → `CountTaggedFlows()`（现状）；`all` → `COUNT(*) FROM flows`（新增 `CountAllFlows`）。
- **`start`/`end`（时间窗口，需求 7）**：unix 毫秒，**含头尾**（`started_at >= start AND started_at <= end`）；`0`/缺省 = 不限，**支持半开窗口**（`start>0,end=0`＝仅下限；`start=0,end>0`＝仅上限，均合法）。SQL 走既有索引 `idx_flows_started`。**校验规则（v3.1）**：仅当 `start>0 && end>0 && start>end` 时返回 400——朴素 `start>end` 比较会把合法半开窗口（如 `end=0`）误杀为 400。
- **`buckets`（直方图分桶数）**：默认 120、上限 500（超出按 500 处理）。
  - 无窗口（start/end 缺省）时：服务端先取 `[MIN(started_at), MAX(started_at)]` 边界再等宽分桶；空库返回空数组。**边界探测谓词口径（v3.1）**：MIN/MAX 带与数据查询**相同的 tagID + scope 谓词**——直方图恒显示「当前取数范围」的分布，避免 archived 视图下底图两端出现空段误导。
  - **分桶守恒（v3.1 修订）**：`width = ceil((t1-t0)/buckets)`（向上取整）；bucket 序号 `(started_at-t0)/width` **钳制到 `[0, buckets-1]`**（(t1-t0) 不整除 buckets 时溢出桶并入末桶，禁止直接按序号索引导致尾部流丢弃）；`t1-t0 == 0`（单流库/同毫秒）时退化为**单桶**（width=1），禁止除零。响应：`{ start, end, buckets: [{ t0, t1, count }] }`（t0 含、t1 不含，末桶 t1=end）；**守恒约束：Σcount == 窗口内流总数**（AC21 校验）。
  - scope/archived 谓词与 flows 列表同一套查询构造（archived 加 `id IN (SELECT flow_id FROM flow_tags)`）。

```sql
-- 直方图查询形态（示意）
SELECT (started_at - :t0) / :width AS b, COUNT(*) AS n
  FROM flows
 WHERE started_at >= :winStart AND started_at <= :winEnd
   [AND id IN (SELECT flow_id FROM flow_tags)]   -- scope=archived
 GROUP BY b ORDER BY b
```

> **路由实现（v2 明确）**：沿用本库现有**前缀注册 + 手动分段解析**风格（表内 `{id}` 仅为示意，非 Go 1.22 ServeMux 通配符）。tag id 恒为 `t_`+hex，与字面段 `flows`、特殊值 `all` 无冲突，无编码问题。
> **详情/正文一律走 tags 命名空间（v2 定稿，删除 v1 摇摆表述）**：现有 `/api/v1/flows/{id}` 与 `/flows/{id}/body` 要求流在内存 store（[bindings_flows.go](../internal/app/bindings_flows.go)），「仅在归档库、内存已淘汰」的流会 404——不复用。

**重命名/删除语义（v2 细化）**：

- **RenameTag(oldID, newName)**：newID = hash(归一化 newName)。若 newID 已存在（改名为既有标签）→ **合并**：同事务 `INSERT OR IGNORE` 迁移 flow_tags 关联、`last_used_at` 取 max、DELETE 旧 tags 行与旧关联；否则 UPDATE tags 行 name。完成后：tagIndex COW 刷新 + 受影响内存流经 pendUp 推送。
- **DeleteTag(tagID, deleteFlows)**：
  - `deleteFlows=false`：仅删 tags 行 + 该 tag 的 flow_tags 关联（flows 保留在库）；
  - `deleteFlows=true`：**同一事务**删该 tag 的 flow_tags 关联 + flows 行 + **bodies 行（按 flow_id 级联，persist 层新增 SQL，v2 补齐）**；
  - **两路径都必须做（v2 新增，封幽灵复活）**：
    1. App 层 tombstone——`deletedFlows map[string]struct{}`（仅 deleteFlows=true 时记录被连删的 flow id；项目切换时清空）挂在 App 上，`onPersistEvent` 入队前命中即丢弃。否则已删流仍存活于内存环形队列时，后续 update 事件（置顶切换等）会让录制 Writer 重新 upsert flows+bodies，**已删数据复活且永不进复盘页**（录制 retention 关闭时永久残留为不可见脏数据）；
    2. tagIndex COW 刷新（删除标签名/清空对应流的名单）+ 受影响内存流经 pendUp 推送（主窗徽章即时清空）。

**persist 层 v3 落点**（[tags.go](../internal/persist/tags.go) 扩展，无 schema 变更）：

- `FlowsByTag` 参数化：`(tagID string, scope string, start, end int64, limit, offset int)`——谓词按 scope 组装（archived 加 `id IN (SELECT flow_id FROM flow_tags)`）、按 start/end 加 started_at 区间；`all` + `archived` 两分支共用 ORDER BY / LIMIT / OFFSET 骨架。
- 新增 `CountFlows(tagID, scope string, start, end int64) (int64, error)`（total 与列表同谓词，避免分页 total 与数据不一致）；
- 新增 `CountAllFlows() (int64, error)`（`COUNT(*) FROM flows`，供 `/api/v1/tags` 的 `totalFlows`）；
- 新增 `Histogram(tagID, scope string, start, end int64, buckets int) ([]HistBucket, error)`（含全域边界探测 `MIN/MAX(started_at)`）。

**跨窗口闭环（v2 新增）**：复盘页的打标/重命名/删除经 ctlService 适配层全部落入上述同一批 App 方法，方法内部统一完成「DB 写 → tombstone/tagIndex 刷新 → pendUp 推送」；主窗侧**不新增 SSE 频道**（flows/status 维持现状），**打开标记弹窗时重拉 `ListTags()`** 即获得最新标签历史。复盘页自身每次管理操作后重拉标签列表。

### 4.6 保留策略与标签的关系（v2 修正落点）

- **归档库（archive Writer）retainDays=0/maxMB=0，不做任何自动删除**——已标记流永久保留，直到用户在复盘页显式删除标签（并可选删流）。
- **录制库**（自动录制开时）的 retention 维持现状（按年龄/容量删最旧），但**排除已标记流**。落点按真实代码形态（v2 修正——v1 只写了单条 DELETE 形态，与实现不符）：
  1. **按龄清理**（`Retention()` 单条 DELETE）：
     ```sql
     DELETE FROM flows
      WHERE started_at < ?
        AND id NOT IN (SELECT flow_id FROM flow_tags)
     ```
  2. **按容量清理**（`enforceSize`）实际形态是「**SELECT 最旧 64 条 id → 逐条 DELETE**」：排除条件加在 **SELECT 的 WHERE**（`AND id NOT IN (SELECT flow_id FROM flow_tags)`）。已验证：全表皆为标签流时 SELECT 返回空 → 提前返回，不会死循环。
  3. **孤儿 body 清理无需改**：标签流的 flows 行永在，body 不会成为孤儿。
  4. flow_tags 表由共享 `migrate()` 创建，录制 Writer 单独打开（archive 从未打开）时上述子查询同样有效。
- → 即**只要流被打了标签，自动录制的保留清理就跳过它**，标签流在两种打开方式下都安全。

### 6.1 构建形态：Vite 多页（MPA）第二入口

- 新增 `frontend/review.html`（与 index.html 平级）+ `frontend/src/review/main.ts` + `frontend/src/review/ReviewApp.vue`。
- `vite.config.ts` 增加 `build.rollupOptions.input`：

  ```ts
  input: {
    main: resolve(__dirname, 'index.html'),
    review: resolve(__dirname, 'review.html'),
  },
  ```

  产出 `dist/index.html` + `dist/review.html` + 共享 assets。
- **红线（v2，P1 级）**：`base` **保持默认 `/` 绝对不动**。Vite 的 base 是全局配置——若按 v1 备选改成 `base: '/review/'`，主窗口 index.html 的资源引用也会变成 `/review/assets/*`，Wails assetserver 在 embed FS 里找不到该前缀 → **主窗口生产 exe 白屏**（vite 绿≠进包同类的低可见度致命故障）。托管侧适配见 §6.3。
- 复盘页独立 createApp，**不依赖 Wails runtime**（`window.go`/`window.runtime` 在系统浏览器里不存在）；数据全部走 `fetch('/api/v1/...')`。
- 复用主应用的展示组件（JsonTree/HeaderTable/BodyViewer/CopyBar 等，按需 import，注意这些组件若耦合了 wailsjs 绑定需解耦或在复盘页用 fetch 版数据源）。主题统一 `n-config-provider :theme="darkTheme"`。

### 6.2 鉴权与 API 基址

- 复盘页 URL：`http://127.0.0.1:9595/review.html?token=<TOKEN>`（由 `GetReviewURL` 返回；token 即 ctlapi token）。
- **token 特性（v2 补充）**：每次启动重新生成（重启即失效），hex 字符集拼 URL 无需编码；浏览器历史里残留的是失效 token，泄露风险低。
- 复盘页启动：从 `location.query` 读 `token`；之后所有 `fetch` 带 `Authorization: Bearer <token>` 头（或 `X-Prism-Token`）。
- SSE（如需实时）用 `EventSource('/api/v1/events?token=...&channels=flows')`（query 鉴权仅 events 允许）。复盘以「查看已归档」为主，**本期不接 SSE 实时**，提供手动刷新即可（跨窗口闭环靠 §4.4 的 App 方法内同步，不靠 SSE）。
- token 缺失/401：复盘页显示「未授权或应用已关闭」空态（ctlapi 随 App 退出而关闭，浏览器窗口留着时 fetch 失败 → 友好提示「PrismProxy 已退出」）。

### 6.3 静态资源托管（Go 侧，v2 定稿：托管整个 dist，零 base 改动）

- ctlapi 目前只注册 `/api/v1/` 路由。新增**非 API 静态托管**：
  - 生产：复盘页静态资源随主前端一起 `//go:embed all:frontend/dist`（main.go 已 embed dist）。将该 `embed.FS` 传入 ctlapi Server，新增路由（**均不套 `s.auth`**；数据 API 仍需 token，token 由页面从 URL query 取出带入 fetch）：
    - `GET /assets/` → 服务 `dist/assets/*`（复盘页默认构建产物以绝对路径引用 `/assets/...`，正好命中）；
    - `GET /review.html` → 服务 `dist/review.html`；
    - `GET /review` → 302 → `/review.html`（友好短链，可选）；
    - `GET /` → 302 → `/review.html`（可选）。
  - 主窗口照旧由 Wails assetserver 服务同一份 dist（index.html 默认入口），与 ctlapi 托管互不干扰；`/api/v1/` 路由显式注册、优先匹配。
  - **为什么不改 base**：见 §6.1 红线（P1）。
- **安全考量（v2 补充）**：
  - 静态 HTML/JS 本身无数据，放行合理；数据 API 全部 Bearer 鉴权；仅绑 127.0.0.1。
  - 跨站伪造面：服务端不返回任何 CORS 头 → 恶意网页对 9595 的 JSON POST 必触发 preflight 且必失败；GET 简单请求无凭据必 401；叠加 Chrome Private Network Access 对公网→本机请求的限制——Bearer 模型基本免疫跨站伪造，维持「静态页放行、数据 API 鉴权」拍板。
  - **固有暴露面明示**：归档正文可能包含敏感凭据，渲染在系统浏览器中存在浏览器扩展/截屏/剪贴板暴露面——复盘页顶部加提示文案「内容可能包含敏感凭据，请勿在共享/录屏环境打开」。
- `wails dev` 下（v2 精确化）：wails dev 的 devserver 端口由 wails 自管，**以启动输出为准（不是 5173）**；5173 仅适用于纯浏览器 mock 预览。真实联调：复盘页访问 wails dev devserver 的 `/review.html`，Vite proxy `/api` → `127.0.0.1:9595`。本期以生产 embed 为准。

### 6.4 复盘页功能

布局：左侧标签侧栏 + 顶部过滤 + 右侧流列表/详情（可复用 NSplit 思路或简单左右分栏）。

- **左侧标签侧栏**：
  - 「全部已标记」（总数）+ 各标签项（名称 + 流计数 + 最近使用时间）；
  - **「全部已标记」总数口径（v3.1 修正）**：改用 `/api/v1/tags` 响应根级 `total`（`CountTaggedFlows()` 去重口径）——**现状实现为各标签 count 累加**（[ReviewApp.vue](../frontend/src/review/ReviewApp.vue) `totalCount = tags.reduce(...)`），流多标签时虚高，v3.1 一并修正；
  - 标签项 hover/右键：重命名、删除（删除弹确认：`仅移除标签关联` / `同时删除标签下的流数据` 二选一，对应 `DeleteTag(flows=0|1)`）；操作后重拉标签列表（主窗侧由 App 方法内闭环刷新，§4.4）。
- **数据范围切换（v3 新增，需求 5）**：
  - 流列表顶栏新增范围切换控件（建议 `n-radio-group` 两段式按钮「**归档数据** | **全部数据**」，拍板 §九 10），**默认「归档数据」**；
  - 「归档数据」= 现状语义（打标流）；「全部数据」= 库内全量（含自动录制落库未打标流，`scope=all`）；
  - **仅当左侧选中「全部已标记」（tagID=all）时可用**；选中具体标签时控件禁用并回退归档语义（tooltip 提示「具体标签下均为归档数据」）；
  - 切换时**列表、total、时间轴（直方图）一并按新 scope 重拉**；顶栏显示当前范围计数（如「归档 128 条」/「全部 512 条」，归档/全部计数来自 `/api/v1/tags` 的 total 与 `totalFlows`）。
- **时间窗口筛选 + 密度时间轴（v3 新增，需求 7）**：
  - 新增组件 `ReviewTimeline.vue`：横向时间轴，底图 = `GET /api/v1/tags/{id}/histogram?scope=&buckets=` 的全域分桶直方图，每桶按 `count` **色彩温度渐变着色**（低密度暗灰 → 紫 → 橙 → 高密度亮黄，空桶无色；梯度拍板 §九 13），hover 显示该桶时间范围与条数；
  - **数据源联动（v3.1 明确）**：直方图随**当前 tagID + 当前 scope** 重拉——tagID=all 时按 scope（archived/all）；选中具体标签时按该标签拉分布（端点 `{id}` 即具体标签 id）；标签切换/范围切换/删除标签/重命名合并后均需重拉底图；
  - **拖拽框选（brush）**：在时间轴空白区按下拖拽 → 半透明选区实时跟随，松手后以选区 `[t0, t1]` 作为窗口刷新列表（flows 请求带 `start`/`end`）；拖拽过程仅显示时间提示、**不触发列表刷新**（防抖抖动）；
  - **手势状态机（v3.1 补，防手势冲突）**：`idle → (mousedown) pressing → (位移>4px) brushing/panning/resizing → (mouseup) done → idle`；
    - pressing 阶段落点在**已有选区**内：按位置三分区——左右缘 ±6px 内进入 `resizing`（对应边缘），中部进入 `panning`；落点在选区外进入 `brushing`（新选区）；
    - pressing → mouseup **总位移 ≤ 4px 判定为单击**：落点在空白处 → 清除窗口（即「单击空白清除」的实现口径，与拖拽天然互斥）；
    - 选区宽度 < 最小窗口（建议 2×桶宽）时丢弃本次操作，防误产生毫秒级窄窗。
  - **布局落点（v3.1 补）**：时间轴置于流列表 pane 顶部**可折叠条**（默认展开；列表 pane 宽 46%，500 桶塞不下——buckets 实际值按容器宽度自适应，上限仍 500）；折叠态保留小色条概览 + 当前窗口指示。
  - **联动边界（v3.1 补）**：scope/标签切换或历史补载导致时间轴底图范围变化后，**已有选区与新区间取交集**——交集为空则自动清除窗口；窗口起止与底图边界不一致时钳制。异步重拉直方图/列表用**代际序号防护**（丢弃过期响应，防快速切换时旧数据回填）。
  - **选区平移/缩放**：拖动已有选区中部整体平移窗口；拖动选区左右边缘调整窗口大小；平移/缩放同样松手后才刷新；
  - **清除窗口**：单击时间轴空白处（非拖拽）清除窗口恢复全量；列表顶栏显示当前窗口起止（可手动点 × 清除）；窗口外桶降透明度以突出选区；
  - **时间轴不随窗口重拉（v3 拍板 §九 12）**：底图固定全域分桶，不做变焦——窗口只作用于列表过滤，实现简单、语义清晰；后续可选增强：窗口重拉直方图（变焦看更细密度）；
  - 范围切换（scope）与窗口（start/end）正交组合，作用于列表与 total。
- **流列表**：选中标签后展示其下流（时间倒序），列复用主列表关键列（时间/方法/状态/域名/路径/大小）；支持关键字过滤（前端本地过滤即可）；长列表按 `limit/offset` 「加载更多」。**v3**：窗口/范围变化时重置分页从第一页拉起。
- **流详情**：点击一条 → 下方/右侧展示概览 + 请求/响应头 + 正文（JsonTree/BodyViewer），数据走 `GET /api/v1/tags/flows/{id}` 与 `.../body`。
- **顶部**：项目名（只读展示当前归档所属项目）、刷新按钮、「在主窗口打开」提示文案、**敏感凭据提示**（§6.3）。
- **空态**：无标签时引导「回到主窗口，选中流量后点顶栏『标记』」。**v3**：库内有自动录制数据但从未打标时（archived 范围空态），提示「暂无归档数据，可切换『全部数据』查看自动保存的流量」。**v3.1 前提修正**：现状 `ReviewFlowList` 在归档 Writer 未就绪时返回**错误**（[bindings_tags.go](../internal/app/bindings_tags.go) `w==nil → fmt.Errorf("暂无已归档的流量")`），复盘页首开会走 fatal 态——v3.1 改为**空态语义**（空列表 + total=0），上述空态引导才成立（落点见 §八）。

## 十、验收标准（草案，v2 增补 AC10–AC17；v3 增补 AC18–AC22）

- **AC1 打标落库**：自动录制关闭时，选一批流打标签 → 重启应用 → 复盘页仍能看到该标签及其流、正文完整可读。
- **AC2 弹窗缓存**：输入标签名、勾选自动清空 → 不重启再次打开弹窗，名称回填、勾选保留；重启应用 → 名称为空、复选框默认不勾；清空图标可一键清空名称。

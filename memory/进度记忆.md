## 列表清空/重置自动回滚顶部（2026-09-18，未提交，npm build 绿 + 浏览器 mock GUI 实测全绿）

- 改动 2 文件：
  - `components/FlowTable.vue`（两页共用，单点兜底）：`watch(() => props.rows.length)` **同步回调**内用 `props.rows.length * props.itemHeight - el.clientHeight` 判越界，越界即 scrollToTop()（不用 nextTick、不读 el.scrollHeight）。

### CLI `--help` 无输出修复（2026-09-19，go build + ctlapi 测试全绿 + 行为实测）

- 用户报「cli help 没有输出」：排查实测 `cli help`（stdout/exit 0）及裸 `cli` 均有输出；真因=文档（AI-CLI使用说明.md §441）推荐的 `cli --help` 形态把 usage 只打到 stderr 且 exit 2（flag 包 ErrHelp 一遍 + 无子命令兜底一遍，共两遍），stdout-only 捕获环境（AI 工具/重定向）表现为无输出。
- 修复（internal/ctlapi/cli.go RunCLI）：`fs.Usage = func(){}` 禁用解析期自动输出；Parse 返回 `flag.ErrHelp` → usage 打 stdout + exit 0（`--help`/`-h` 与 `cli help` 等价）；解析错误/无子命令仍 stderr + exit 2（flag 包错误行自带，usage 不再重复）。
- 验证：`go build ./...` + `go test ./internal/ctlapi/` 全绿；编译后实测 help/--help/-h → stdout+exit 0，裸 cli → stderr+exit 2。正式 exe 因 PrismProxy 进程运行中未覆盖重建，关闭后需 `wails build`。
- 第二层根因（用户 trae-preview cmd 终端复测仍无输出后定位）：wails windowsgui exe 从 cmd 直接启动时 GetStdHandle 为 NULL，输出静默消失（PowerShell/管道启动不受影响）。新增 main_windows.go `attachParentConsole()`（main_other.go 空实现）：CLI 入口检查 std 句柄，无效则 AttachConsole 父控制台并把 stdout/stderr 重接 CONOUT$、stdin 接 CONIN$（详见教训 55）；main.go cli 分支接入。`wails build` 重建成功（24s），新 exe 实测 help/--help/-h → stdout 9187B+exit 0、裸 cli → stderr+exit 2。
